# WS-ENG-009-03 — Make Commitrail contribution paths consistent

- Initiative: WS-ENG-009
- Durable disposition: Complete
- Intended merge outcome: Support standalone change records, document the exact
  PR-only editorial boundary, and remove obsolete sequencing language.

## Intent

Contributors must be able to use the small contribution paths advertised by
Commitrail without creating an unnecessary initiative or duplicating GitHub state.
The current validator requires an overview for every record and a record for
README changes even though documentation advertises a PR-only correction path.

## Bounded change

Allowed: `scripts/check_commitrail_records.py`, focused
`scripts/test_commitrail_contribution_paths.py`, `.github/workflows/agent-gates.yml`
(register that test module only), `.commitrail/README.md`,
`.commitrail/CHANGE_TEMPLATE.md`, `CONTRIBUTING.md`, `AGENTS.md`,
`.commitrail/INDEX.md`, WS-ENG-009 `OVERVIEW.md` and this record,
WS-QUAL-003 `OVERVIEW.md`, and relevant contribution skills only if their
instructions contradict the new paths.

Not allowed: product code, tests or coverage-floor weakening, archive edits,
GitHub permission changes, PR-body authority, new automation services, or
changes in another agent's worktree.

## Design and decisions

- Keep existing initiative records valid. Add `.commitrail/changes/<slug>.md`
  for a meaningful standalone change; validate the same required content and
  dispositions without requiring an initiative overview or index row.
- Continue requiring one record for implementation and process-control paths.
  README and ordinary documentation corrections may use PR intent/scope only;
  document that substantive specification changes still need a record through
  human review. No path heuristic claims to establish semantic risk.
- Preserve index/overview consistency, Markdown structure validation, immutable
  pre-cutover custody and rejection of transient declarations.
- Clarify that the test audit sequences its own PRs while bounded product work
  proceeds concurrently with explicit file ownership. Remove the index-wide
  reconciliation watermark instead of maintaining another global timestamp.

## Acceptance criteria

- Standalone backend changes pass with one complete standalone record and no
  initiative; malformed standalone content fails the existing field checks.
- README/docs editorial-only changes need no record; mixed backend/process
  changes still require one. Exactly one record is counted across both layouts.
- Existing initiative ownership and overview checks remain effective.
- Contributor instructions describe the implemented paths and their semantic
  review limits. QUAL-003 no longer blocks unrelated bounded product work.

## Risk and review routing

- Risk class: L1, bounded deterministic CI gate policy.
- Required reviewers: CI integrity, QA/test delta, documentation; reuse review
  of the shared record parser. Focused plan inspection before implementation.
- Human review focus: narrower paperwork without weakening implementation proof
  or reintroducing a second permission system.

## Evidence

Run focused contribution-path tests plus existing Commitrail contract, archive,
Markdown structure and lightweight-gate regressions. Negative controls must
reject recordless mixed changes, two records across layouts and malformed records.
Run Commitrail validation, Markdown links, stale wording and diff checks.
Hosted CI owns full backend verification. Passing structure checks do not prove
that recorded product capabilities are implemented.

The existing 68 regression tests and 10 focused contribution-path tests pass.
Running the standalone and README regression tests against the original
validator from main makes both tests fail with the original
`COMMITRAIL_CHANGE_RECORD_REQUIRED` error, after fixture setup succeeds.

## Review findings

Plan review found no blocker. Its malformed-name counterexample was adopted:
an invalid standalone path cannot hide alongside a valid record. The final
candidate's review and hosted execution evidence belongs to the PR.

## Reconciliation

Based on main through PR #374. PR #375 owns the current test-audit slice; retain
its changes when integrating any overlap in the QUAL-003 overview. No product
implementation or subsequent initiative is started by this change.
