# WS-MCP-002-09 - Draft review and revision policies

- Initiative: `WS-MCP-002`
- Durable disposition: `Complete`

## Intent

Let an authorized human Project Manager append and select review and revision
rules for one draft guide through MCP. Workstream remains the sole authority for
authorization, policy semantics, immutable lineage, optimistic preconditions
and replay.

## Current behavior

Main at `6fa9a9b55` exposes keyed review- and revision-policy `PUT` operations.
Each requires a caller-owned `If-Match` selector: `"no-current-policy"` for the
first version or the exact opaque selector derived from the selected policy.
Before this chunk the merged adapter had twenty-five tools; this chunk completes
the proposed twenty-seven-tool catalogue.

## Design and decisions

Expose exactly `workstream_review_policy_put` and
`workstream_revision_policy_put`. Both accept typed project/guide selectors,
a caller-supplied UUID idempotency key and an explicit transport-safe
`if_match` argument. The adapter forwards the bearer, body, key and selector
unchanged to one fixed public route. It never reads mutation values from MCP
HTTP headers or `_meta`.

The adapter validates the current public request shapes, including explicit
human-review mode when supplied and the backend's bounded revision semantics.
Omitted optional fields remain omitted so Workstream applies defaults or
inherits the current review mode. A successful response must bind the project,
requested policy fields and initial/current predecessor lineage. Unverifiable
success becomes uncertain execution.
