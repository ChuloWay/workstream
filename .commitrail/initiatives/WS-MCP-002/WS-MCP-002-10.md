# WS-MCP-002-10 - Contributor workspace and contribution policies

- Initiative: `WS-MCP-002`
- Durable disposition: `Complete`
- Intended merge outcome: Expand the independent MCP adapter from 27 to 47 tools with contributor workspace, contribution evidence and contribution-policy operations.

## Intent

Let authenticated contributors inspect their current Workstream state and let
authorized project/Finance actors inspect and manage contribution policies
through the same fixed-route, caller-token MCP boundary.

## Current behavior

Main at `bb39ac10a` exposes 128 public `/api/v1` operations. The merged MCP
adapter binds 27 of them. The maintainer requested broader parallel domain
batches, using the nearly complete CLI wire mapping as reference while the MCP
continues to call the public API directly.

## Bounded change

### Allowed

- `mcp_server/`: 20 selected public contracts, two domain tool modules, fixed
  gateway/schema/registry bindings, focused tests, package contents and docs.
- `.github/workflows/mcp.yml`: exact 47-tool container assertion.
- This record, the initiative overview/index and capability status.

### Not allowed

- No backend, CLI, database, authorization or identity behavior changes.
- No CSV/binary MCP output, generic HTTP tool, private backend import, direct
  database access, local policy authority, generated mutation key or retry.
- No guide lifecycle, checker/artifact, task execution or operations/import tools.

## Design and decisions

The batch adds 13 contributor/project workspace reads, three contribution-policy
reads and four keyed contribution-policy mutations. Contribution exports are
JSON-only: `format` is not a tool argument and the gateway always sends
`format=json`. All routes are fixed and all output schemas are selected from the
current backend OpenAPI document.

Workstream remains authoritative for visibility, pagination, policy validity,
authorization and replay. Successful policy mutation receipts must match the
caller-supplied operation, project, policy and version identities. Any
unverifiable mutation success is uncertain execution.

This record supersedes the earlier use of ID 10 for a 27-tool-only release
proof. The maintainer's later expansion direction changes the initiative to
five implementation batches, followed by assembled release proof after the
public surface is covered.

## Acceptance criteria

- [x] Exactly 47 unique tools and zero resources/prompts.
- [x] Twenty selected OpenAPI snapshots are tamper-evident and drift-tested.
- [x] Workspace filters/cursors are typed and fixed-route calls forward the bearer once.
- [x] Contribution output is JSON-only and cannot be switched to CSV by the caller.
- [x] Policy keys/bodies/selectors are typed; invalid input never dispatches.
- [x] Policy receipts bind operation/project/policy/version identities.
- [x] No local authorization, replay state, database access or automatic retry.

## Risk and review routing

- Required reviewers: security/authorization, architecture/reuse, QA/test delta,
  documentation and CI integrity.
- Human review focus: fixed route/query mapping, contribution data exposure,
  policy receipt lineage, no token leakage and no local authority.
