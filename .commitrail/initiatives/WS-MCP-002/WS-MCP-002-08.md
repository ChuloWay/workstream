# WS-MCP-002-08 - Guide declarations and draft metadata

- Initiative: `WS-MCP-002`
- Durable disposition: `Complete`
- Intended merge outcome: Add two fixed public-API guide metadata mutations to the independent MCP adapter.

## Intent

Let an authorized human Project Manager declare one draft guide's illustrative
tasks and document metadata, then edit only its change summary through MCP.
Workstream remains the sole authorization, draft lifecycle, version-conflict,
document-custody and replay authority.

## Current behavior

Main at `a82f0d45e` exposes keyed guide create and update operations. Creation
requires a version, bounded task examples and 1–100 document declarations, then
returns a draft guide, immutable document identifiers and an
`awaiting_documents` setup identity. Update accepts only `change_summary`.
Before this chunk the merged adapter had twenty-three tools; this chunk raises
the catalogue to twenty-five.

## Design and decisions

Expose exactly `workstream_guides_create` and `workstream_guides_update`.
Both accept typed project selectors and caller-supplied UUID idempotency keys in
tool arguments, then forward the caller bearer, body and key unchanged to one
fixed public route. Create accepts only the current API's version, optional
change summary, task examples and document declarations. Update accepts an
exact guide UUID and a body containing only the optional change summary.

The adapter enforces closed schemas, meaningful task-example content and the
backend's canonical 128 KiB UTF-8 aggregate example limit. It binds successful
responses to the requested project, guide, version, summary, examples,
document order/media type and waiting setup status. It stores no guide or upload
state, retries no mutation and reports unverifiable success as uncertain execution.
