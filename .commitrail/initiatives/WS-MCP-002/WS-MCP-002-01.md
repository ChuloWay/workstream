## Design and decisions

Use the official SDK and the agreed protocol profile in an independent Python
package/container. Pin an exact supported SDK version and interpreter after
checking the current official release; no floating dependency or silent
protocol downgrade. The existing SDK v2 direction is a compatibility decision
to verify, not evidence that a particular release is available.

Register exactly one tool. Validate transport metadata, Origin and the incoming
credential, then dispatch one fixed GET to the configured public API. No actor
selector, token, arbitrary URL or caller-defined authorization header appears
in arguments. Preserve the declared profile result, safe errors and correlation
metadata. The backend remains authoritative for caller admission and permissions.

Use bounded request/response sizes, bounded timeouts/concurrency, no redirects,
per-request credential context and no automatic HTTP retries in this foundation.
Reject unknown tools before dispatch. Apply authenticated `Cache-Control:
no-store` to success and errors and document proxy preservation. No database,
backend startup imports, refresh tokens or local permission cache are needed.

### Required decisions before protected dispatch

Record joint catalogue/schema agreement and the credential contract in the
overview before implementing code that depends on them. That contract must
name the MCP and API resources/audiences, owner-supported downstream credential
mechanism, human identity preservation, issuer/key source, registered client
and validation environment. If no supported mechanism exists, report the
owner dependency; do not invent a bridge or downgrade credential verification.
Capture the exact selected OpenAPI operation and custom-validator semantics
against an agreed runtime baseline. A newer main commit does not silently
change the pinned handoff. This contract remains proposed while those decisions
are unresolved. Packaging exploration does not make protected dispatch approved.

## Review findings

The API handoff and mapping address the maintainer's request for an explicit
27-tool inventory. Health and service provisioning are excluded; guide inputs
and policy omission behavior are corrected in the overview. Privacy allows
authorized declared response fields while excluding credentials and sensitive
diagnostics. Conditional MCP headers and authenticated no-store are retained.
Neither this mapping nor a positive review reaction completes joint catalogue
freeze or resolves the credential contract.

The overview now makes mutation ingress explicit: typed tool arguments supply
the downstream replay key and policy selector, without metadata/header fallback
or normalization. Adapter shape/header-safety validation is distinct from
Workstream's policy preconditions and persistent replay ownership. Per-binding
tests cover rejection, exact forwarding and restart replay. These are later
mutation-chunk requirements; the first profile-read chunk adds neither field.

The first draft added a second planning record and failed the existing
Commitrail one-record gate. Consolidating the planning evidence into this
first contract removes the duplication; no gate or workflow is changed.

The maintainer requested a smaller first proof rather than a full adapter PR.
The contract exposes one read and excludes all mutations. Catalogue agreement
and the credential boundary must precede protected dispatch. The proposed
upload and policy-selector gaps remain explicit in the overview and are not
repaired through scope expansion here.
