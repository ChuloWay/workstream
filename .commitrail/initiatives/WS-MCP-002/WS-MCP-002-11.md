# WS-MCP-002-11 - Guide, checker and artifact operations

- Initiative: `WS-MCP-002`
- Durable disposition: `Complete`
- Intended merge outcome: Expand the independent MCP adapter from 47 to 90
  tools with the current public guide lifecycle, checker and operator-artifact
  operations.

## Intent

Let authorized Workstream callers complete guide setup and activation, inspect
and recover checker execution, and inspect or recover artifact operations through
fixed MCP tools. The adapter forwards the caller bearer unchanged; Workstream
continues to own identity, authorization, replay and lifecycle truth.

## Bounded change

### Allowed

- `mcp_server/`: 43 selected public contracts, guide/checker/artifact tool
  modules, fixed gateway/schema/registry bindings, focused tests and package docs;
  reconcile existing selected snapshots when current backend OpenAPI drift would
  otherwise fail the exact-contract gate.
- `.github/workflows/mcp.yml`: exact 90-tool container assertion.
- This record, the initiative overview/index and affected capability status.

### Not allowed

- No backend, CLI, database, authorization or identity behavior changes.
- No generic HTTP tool, private backend import, direct database access, local
  authorization/lifecycle/replay state, generated mutation key or automatic retry.
- No task claim/start/submission, task management/import, audit or service-actor
  tools.

## Design and decisions

The PR combines the two previously planned adjacent batches because the
maintainer requested broader parallel coverage. It adds 24 guide operations for
reads, verified document bytes, setup/sufficiency and artifact policies,
proposals, corrections, approvals and activation; it also adds 10 checker and
delivery/registry operations plus nine operator-artifact operations.

JSON operations use selected OpenAPI response schemas. Guide document upload
accepts bounded Base64 only at MCP ingress and forwards decoded bytes with the
declared media type; document reads return bounded Base64 plus server-observed
size and SHA-256. Ordinary JSON retains its separate 64 KiB default bound;
document transfers use a 64 MiB cap and 120-second timeout without increasing
the memory or timeout allowance for other operations. Route selectors and
mutation receipts are bound only against their authoritative response fields.
Missing response selectors are never inferred from unrelated nested identifiers.

The current-source reconciliation also refreshes fourteen existing snapshots.
Ten changes remove backend schema descriptions only; four guide/post-policy
snapshots adopt the backend's explicit input/output target-schema split. Routes,
methods and the already exposed tool catalogue are unchanged by that refresh.

## Acceptance criteria

- [x] Exactly 90 unique tools and zero resources/prompts.
- [x] Forty-three selected OpenAPI snapshots are tamper-evident and drift-tested.
- [x] Every fixed method/path/status binding matches its reviewed snapshot.
- [x] Typed invalid input and malformed or substituted success responses fail closed.
- [x] Binary guide bytes are bounded, typed and digest-reported without logging payloads.
- [x] Retry/reconcile/register mutations preserve caller keys and uncertain execution.
- [x] No local authorization, replay state, database access or automatic retry.

## Review findings

CodeRabbit findings were accepted and fixed: the remaining-operation count is
101; JSON and document response limits are independent; document transfers use
their own bounded timeout; oversized document reads fail deterministically and
non-retryably; and submission-artifact policy list responses now bind through
an explicit operation set with a positive regression case. Focused tests and the
full non-integration suite passed after the fixes. GitHub owns transient review
conversations and exact-head approval.
