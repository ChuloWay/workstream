# WS-MCP-002-06 - Project shells

- Initiative: `WS-MCP-002`

- Intended merge outcome: Add two fixed public-API project-shell tools to the independent MCP adapter.

## Intent

Let an authorized human Project Manager create a draft project shell and let an
authorized human read one project through MCP, while Workstream remains the sole
authorization, projection, lifecycle and replay authority.

## Current behavior

Main at `51b868071` exposes authoritative project creation and project read
operations. Project creation requires current system Project Manager authority
and a caller-supplied UUID idempotency key. Project read selects either the full
administrative projection or the exact three-field contributor projection from
the authority Workstream matched. Before this chunk, the merged adapter had
sixteen tools and no project-shell binding. This chunk raises the catalogue to
eighteen tools.

## Design and decisions

Expose exactly `workstream_projects_create` and `workstream_projects_get`.
Create accepts a closed `ProjectCreate` body and required UUID
`idempotency_key`, then forwards the body, caller bearer and key unchanged to
`POST /api/v1/projects`. The adapter never accepts the key from MCP transport
headers or metadata, generates one, stores replay state or retries automatically.
Workstream owns manager authority, duplicate slugs, in-progress operations and
durable replay. An explicit `idempotency_pending` remains retryable for a later
caller-controlled recovery; uncertain execution remains non-retryable.

Read accepts one project UUID and calls only `GET /api/v1/projects/{project_id}`.
The selected OpenAPI contract is a union: Workstream returns the full project to
administrative authority or exactly `id`, `name` and `status` to exact-project
contributors. The adapter validates that union and binds the returned UUID to
the requested project. It does not infer authority or add fields.
