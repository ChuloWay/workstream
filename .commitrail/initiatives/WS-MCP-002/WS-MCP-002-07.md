# WS-MCP-002-07 - Project participation

- Initiative: `WS-MCP-002`
- Durable disposition: `Complete`
- Intended merge outcome: Add five fixed public-API project-participation tools to the independent MCP adapter.

## Intent

Let an authorized human Project Manager discover privacy-safe contributor
candidates and issue, inspect and revoke exact-project submitter or reviewer
grants through MCP, while Workstream remains the sole authorization,
qualification, lifecycle and replay authority.

## Current behavior

Main at `ae1b33eff` exposes authoritative candidate discovery and project-role
grant issue/list/read/revoke operations. Mutations require current authority,
explicit qualification evidence and caller-supplied UUID idempotency keys.
Before this chunk, the merged adapter had eighteen tools and no project-role
binding. This chunk raises the catalogue to twenty-three tools.

## Design and decisions

Expose exactly `workstream_contributor_candidates_list`,
`workstream_project_grants_issue`, `workstream_project_grants_list`,
`workstream_project_grants_get` and `workstream_project_grants_revoke`.
Every tool accepts a typed project UUID and calls only its fixed public route.
Reads preserve optional filter omission and opaque cursors. Successful grant
reads are bound to the requested project and, for one-item reads, grant UUID.

Issue accepts one closed body with target actor, submitter/reviewer role,
explicit bounded qualification evidence and reason. Revoke accepts the
canonical grant UUID and a reason. Both accept a typed UUID `idempotency_key`
and forward it unchanged as `Idempotency-Key`; MCP headers and metadata cannot
supply it. Workstream owns candidate visibility, target eligibility, grant
authority, duplicate/current-state checks, concurrency and durable replay. The
adapter stores no grant state, retries no mutation and treats an unverified
successful mutation response as uncertain execution.

## Acceptance criteria

- [x] Exactly twenty-three tools and zero resources/prompts; all five new input schemas are closed.
- [x] Valid calls perform one exact fixed request with unchanged caller bearer,
  body, filters, cursor and typed key.
- [x] Missing/invalid project, grant, target, role, qualification, reason, page
  or key inputs reject before dispatch.
- [x] Candidate/grant reads validate current selected contracts and prevent
  cross-project or cross-grant response substitution.
- [x] Issue/revoke responses bind project, target, role, grant, status and version;
  malformed or substituted mutation success is uncertain.
- [x] Workstream denials remain unchanged-state outcomes and expose only approved
  status/code/correlation data.
- [x] Real isolated PostgreSQL proof covers populated cursor pages, both roles,
  qualification readback, replay/mismatch/duplicate/concurrency, cross-project
  concealment, ordinary-user denial and revoked contributor access.
