## Intent

Prepare the shared acceptance operation for both human accept and automatic
false-policy acceptance. Serialize future acceptance writers with lifecycle
changes through one REV-owned lock, without creating another availability flag
or requiring live human review first.

## Current behavior

FinalAcceptance source storage still lacks mandatory originating AUTH custody.
There is no lifecycle controller, fulfillment-obligation root or ordinal owner.
The existing AUTH activation contract carries four phases but its generation
constraint cannot describe the first disabled controller. The older split parent
is not an executable implementation contract.

## Design and decisions

REV owns `JointLifecycleReleaseControl` and its public fence contract under
`reviews/api`. One UUIDv7 controller is inserted by migration using the canonical
ID factory, with singleton=true, phase=disabled, generation=0 and database time.
Zero is structural genesis, never an authorized usable generation. Database
checks and immutable INSERT/UPDATE/DELETE/TRUNCATE guards prevent a second row,
bootstrap activation or loss of the controller. A later authorized-transition
migration extends this same table; it does not introduce another controller.

The public frozen snapshot contains singleton identity, phase, generation and
creation time. No fabricated authorization digest or reviewed manifest is added.
The four phases remain disabled, shadow, live and draining. AUTH retains its
independent scalar projection to avoid an AUTH↔REV import cycle; a parity test
protects the closed vocabulary. Its adjacent-transition assertion is inert owner
input, not proof of permission or adjacency. Legal transitions, history and
manifest-bound phase changes belong to the later authorized REV operation.

The PostgreSQL fence requires an already active caller-owned root transaction
and rejects nested transactions. It acquires one fixed namespaced advisory
transaction lock before locking the singleton row, checks the expected
generation and returns detached facts. It never commits, creates a savepoint,
changes the controller, or authorizes a business effect. Missing/malformed
controller or stale generation fails closed. Callers must retain their root
transaction through their future protected operation. Current facts are always
disabled; no production business writer is wired to this mechanical port yet.

Fulfillment ordinals belong to actual CON roots, which do not exist yet. Do not
implement an unconsumed allocator or treat an award/outbox row as a substitute.
A new root gets one immutable ordinal; same-root retries/requeues retain it.
The later real root owner and authorized transition/drain work must prove
writer-versus-cutoff behavior with actual authority before activation. This
chunk proves lock mechanics only, not successful authorized acceptance or drain.

## Acceptance criteria

- Fresh/upgrade databases contain exactly one disabled generation-zero UUIDv7
  controller with database-owned time; retained owner records remain unchanged.
- Direct SQL cannot add, activate, modify, delete or truncate that controller.
- Frozen strict scalar facts reject wrong types, extras and inconsistent genesis;
  AUTH/REV phase values agree without cross-owner private imports.
- Fence requires an active root transaction, rejects savepoints and stale
  generation, and returns canonical detached facts. A failed/missing controller
  cannot produce an authorization capability.
- Independent sessions prove advisory serialization, row locking and release on
  caller rollback/commit. Prove the advisory test fails when only that acquisition
  is removed: use an advisory-only contender so row locking cannot mask the defect.
- No route, evaluator, registration, acceptance source, contribution, award or
  obligation is created. Existing action remains unavailable.
- Alembic/ORM/reset inventories and exact behavior ownership agree. Full hosted
  suite retains completeness; no skips, weakened checks or percentage gates.

## Review findings

Discovery found missing genesis semantics, missing actual CON ordinal storage,
and an AUTH-before-consumer sequencing gap. The bounded design removes the
speculative allocator and defers positive writer/cutoff proof until real owners
and authority exist. The explicit AUTH no-REV-import contract rules out sharing
REV's enum by introducing a dependency cycle.
