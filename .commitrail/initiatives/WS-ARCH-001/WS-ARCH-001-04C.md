# ARCH-04C — Durable post-submit execution and current results

- Initiative: `WS-ARCH-001`
- Durable disposition: `Planned`
- Intended merge outcome: One hidden CHECKERS execution path reserves the exact request, fences workers, evaluates registered structural rules against verified material, and atomically records immutable results and their completion event; production authority and dispatch remain unavailable.

## Intent

Continue claim -> ZIP upload -> pre-submit feedback or immutable Submission ->
automatic post-submit evaluation -> outcome. The no-human-review branch still
requires shared FinalAcceptance, ContributionRecord and applicable awards before
live human review/revision becomes a dependency. This chunk supplies durable
evaluation facts; it does not accept contributions or route TASK state.

## Current behavior

Main `bb640f0a` includes ARCH-04B2. CHECKERS owns the materialization and output
consumer contracts; ART supplies their implementations. POL-07 has one phase
facade, but its post-submit implementation is unavailable. The registered
structural handlers and compiled policy already exist. Their definitions permit
zero generated bytes/output roles and no external provider recovery.

Existing `checker_runs` and `checker_results` preserve retained history, with
immutable ownership and completed outcomes. They have no exact evaluation
request or worker-lease custody. Their mutable current flag and old trigger-auth
fields cannot become the new execution authority. There is no live checker
dispatcher to preserve.

## Design and decisions

1. Extend the existing CheckerRun as the logical attempt. Its UUID is the phase
   attempt ID; persist the exact immutable request envelope/hash, opaque request
   ID, phase, generation, active execution lease and terminal result facts there.
   Existing CheckerResult rows remain the sole member-result history. Remove
   superseded trigger-auth/current-flag fields and update affected readers and
   fixtures together. No one-to-one execution sidecar or second history store.
2. Add one CHECKERS-owned per-Submission fence pointing at the current run.
   `reserve_current_evaluation` creates/replays a queued run and advances that
   fence only in an existing, non-nested caller transaction. Initial generation
   is one; successors must be exact monotonic next generations and reference the
   prior run. Identical request replay returns the winner; the same request ID
   with different envelope is a conflict. It flushes, never commits or executes.
   Future 04E composes this participant with TASK's dispatch outbox atomically.
   No production route/handler receives it in this chunk.
3. Execution never creates or advances the fence. Fresh execute authority is
   prepared before CHECKERS locks, then exact fence/run facts are consumed to
   claim a database-timed lease. An active lease denies another worker; expiry
   may replace only lease ID/generation, preserving run/request identity.
   Completed and terminal infrastructure-failed attempts replay their retained
   outcome; they never restart execution. Old workers cannot finalize after
   takeover or request supersession. Lease generation is not evaluation generation.
4. Release all row locks and prepared authority before ART materialization and
   evaluator work. Consume CHECKERS-owned `PostSubmissionMaterializationPort`;
   ART verifies exact stored bytes/manifest, scopes scratch and cleans it before
   finalization. Invoke `CheckerRegistry.run` for the exact compiled entries and
   sanitize its outcomes through the existing bounded result adapter. Do not add
   a second member dispatcher. Recover unfinished work with the same logical run;
   only these registered, side-effect-free structural handlers may be rerun.
5. Finalization obtains separate fresh finalization authority before feature
   locks, locks fence then run, checks current request and exact unexpired lease,
   validates the complete ordered member set and locked blocking policy, then
   writes members, terminal phase result and shared-outbox completion together.
   Finalization authority binds the result digest and exact output-binding set;
   execute authority cannot substitute for it. No lock or PREP crosses I/O.
   Failure to append or consume authority rolls back every final effect.
6. Current definitions require an exact empty output set. The real reservation
   reader validates run/request/lease and returns zero slots; any claimed output
   slot rejects. Finalization rejects extra bindings instead of fabricating logs
   or calling storage without a supported producer. ART's nonempty controlled
   custody proof remains with 04B2. A future output-producing registered capability
   must add its real producer and atomic binding proof before activation; no
   hypothetical output/provider framework is implemented here.
7. Attempt states are queued -> running -> completed | infrastructure_failed.
   Expired-running takeover retains running state and the same attempt. Only
   completed attempts can supply a current-result reference. Infrastructure
   failure is immutable terminal history, never a routable result; a later
   authorized request must use the next coordinated generation. Completed
   results derive routing from the exact locked blocking severities: any blocking
   task_configuration member yields task_setup_blocked; otherwise any blocking
   submission_structure member yields needs_revision; otherwise allow_review.
   A completed result recommends allow_review only with no blocking member under
   the locked policy; warnings retain their declared semantics. CHECKERS never
   returns accept or mutates TASK. Database constraints/triggers protect immutable
   envelopes, exact parent ownership, lease progression, terminal/member custody,
   sole currentness and terminal result/member/routing consistency. SQL must fail
   closed on null or incomplete facts. History derives currentness from a completed
   run matching the fence; no second mutable current flag remains.
8. Only completed evaluation publishes a bounded CHECKERS-owned completion envelope through the existing
   flush-only OutboxAppendPort in the final transaction. It carries exact
   project/Submission/request/generation/run/result digest, recommendation, empty
   verified binding set and phase authority evidence references, not private
   packet/policy/provider data. It states currentness at publication, not perpetual
   authority: 04E must recheck the current fence on consumption. No handler is
   registered here and no second worker/broker hop is introduced.
9. Authority remains action-specific and deny-only in application composition.
   Strict controlled test participants prove service ordering and rollback, not
   real AUTH catalogue/audit custody. Opaque evidence references in hidden tests
   are not fabricated allow events. 04D supplies actual action-bound adapters and
   database evidence parity, including real audit action/resource constraints,
   before activation. No fake audit foreign key is introduced here. The frozen request is a coordinated
   value, not proof of TASK/PROJECTS source derivation: 04E owns the canonical
   summary/attestation/criteria/evidence/policy-input producer; ART already proves
   the selected immutable Submission bytes and ownership. No private source lookup.
10. Migration 0008 locks/checks retained checker history before reshaping it and
    refuses any nonempty run/result tables. It invents no request, deletes no row
    and leaves schema/data intact on refusal. An environment with retained history
    needs a separately authorized preservation design before applying this migration.
    This is an explicit deployment limitation of replacing unreleased development
    schema, not a fallback implementation. Test fixtures use canonical new custody.

## Acceptance criteria

- Default composition denies before protected reads, scratch, provider or registry
  access. Coordination is caller-transaction-only and unavailable from public entry points.
- Real PostgreSQL proves same-request replay, changed-envelope conflict, exact
  successor, rollback and concurrent initial reservation without duplicate attempts.
- Execute/finalize authorities cannot substitute; late denial leaves no terminal
  result or completion event. Transactions/locks are absent during evaluator I/O.
- Real verified ZIP materialization executes the full current structural policy,
  records exact members and an empty output set, and replays without a second run.
- Current-result reads conceal independently valid foreign project/task/submission/
  request combinations and return only a completed run matching the exact fence.
- Worker takeover preserves attempt identity; old-worker finalization rejects in
  both completion orders. Supersession rejects stale completion and retained events
  cannot assert currentness. Terminal infrastructure failure does not restart.
- Required blocking failure and allow_review cannot coexist, including direct SQL;
  warning-only cases, setup faults, incomplete/foreign members and extra output
  references have distinct valid controls and rejection proof.
- Final members/result/event commit atomically; actual append failure rolls back.
  Envelope/result/member/parent mutation and post-completion appends reject.
- Migration refusal preserves retained data/schema; affected history privacy,
  ownership and nested-result proofs remain after fixture/currentness replacement.

## Risk and review routing

- Risk class: L1, one bounded CHECKERS execution/evidence owner with schema changes.
- Required reviews: architecture/reuse, security, QA/test delta, product/operations,
  senior engineering, documentation and CI integrity for registration/schema changes.
- Human focus: sole currentness, lease/replay identity, migration refusal, exact
  hidden authority boundary, complete member blocking and atomic completion.
- The cohesive owner/schema/history replacement exceeds the usual 500-line L1
  guideline. Splitting schema from its minimal writers would leave required
  custody unenforced; keep one owner implementation with focused modules/tests.

## Plan review disposition

The skeleton incorrectly assigned a new Celery path and hypothetical provider/output
proof to this zero-output structural catalogue. Use the existing phase facade and
later shared-outbox delivery instead. A queued run plus one currentness fence avoids
both a duplicate execution sidecar and an overwritten request without a retained
attempt. Prepared execute and finalize authority remain distinct. Source derivation,
real AUTH evidence and broker delivery are explicit later owner proofs.
