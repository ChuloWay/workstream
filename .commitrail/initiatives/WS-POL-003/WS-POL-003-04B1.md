# POL-04B1 — Unified compilation trigger authority

- Initiative: WS-POL-003
- Durable disposition: Planned
- Risk: L1 — authorization, immutable request custody and PostgreSQL guards.
- Intended merge outcome: the existing hidden compilation request operation
  admits an automatic source-ready trigger with truthful fixed-service and
  source-operation provenance; human replay rechecks current PM authority in
  the same transaction. No live inference switch occurs in this prerequisite.

## Human intent and product sequence

A newly added guide runs unified compilation automatically through Celery once
its source material is verified and prepared. Sufficient results contain findings
and both pre-submission intake and post-submission evaluation policy proposals;
insufficient results contain blocking findings. Both stop for the Project Manager.
Compilation does not approve policies or activate a guide.

The manager can correct the guide or a false model finding and manually request
a fresh run. No automatic/manual product setting is needed. Manual correction
creates a new immutable generation through POL-05, then uses the same compilation
operation. Delivery recovery resumes one attempt; it cannot run the provider a
second time. Preserve original results, authorization and locked lineage.

04B1 supplies missing request authority and database custody. 04B then connects
the existing Celery/executor/projections/finalizer and physically removes the
superseded three inference paths. POL-05 supplies manager correction/generation
creation and proposal approval as already planned. This is the same initiative;
there is no new inference subsystem or repository-wide cleanup prerequisite.

## Why this prerequisite exists

Existing request custody requires a human PM grant in AUTH and PostgreSQL 0008.
Automatic execution cannot fabricate a human request or borrow the source-event
permission as compilation authority. Existing execution/projection/finalization
ports already provide the remaining operation and are not rebuilt.

## Allowed scope

- Existing AUTH compilation public facts/port, adapter, resource/prepared parsing,
  action/service mapping and audit digest integration, with one bounded automatic
  request action under the existing compilation execution permission. Preserve
  exact human PM request authority and fixed PROJECT_SETUP identity.
- PROJECTS guide-compilation request service/repository/models/validation/context
  and public hidden command contracts; source/setup reads through existing owned
  models. Reuse the CHECKERS public catalogue and ART verified-material port.
- One additive Alembic migration replacing the affected request insert/digest
  guards and adding immutable trigger/origin evidence to the same request table.
  No retained data deletion, rewrite of prior evidence, second table, or fallback.
- Focused AUTH/PROJECTS pure and PostgreSQL tests, their explicit lane ownership,
  and affected current specs/initiative/roadmap navigation. Boundary ledgers only
  if existing protected edges actually disappear or new public surfaces require it.

## Prohibited

No HTTP/Celery live cutover, provider call, new provider attempt algorithm,
projection/finalization rewrite, guide correction operation, policy approval,
checker execution or activation. No mode configuration, new readiness state,
parallel request persistence, global cleanup or retained-data deletion.
Existing superseded inference consumers are removed in the following live cutover;
this prerequisite must not add aliases, stubs or compatibility branches for them.

## Design and implementation plan

1. Extend the single request contract with explicit trigger evidence: a human PM
   request or automatic source-ready request. Automatic origin binds the exact
   committed source-snapshot mutation operation/authorization event, project,
   guide, snapshot and setup generation. This is trigger provenance, not version
   compatibility. Reject incomplete and mixed evidence tuples.
2. Resolve automatic input from canonical owned rows and ART-loadable verified
   material. Derive the immutable context and existing attempt identity using the
   single public pre/post catalogues. The callback supplies a setup selector,
   never provider input, authority or claimed hashes. Missing/unready/stale
   material creates no request. Do not add another readiness state.
3. Fresh PROJECT_SETUP authority authorizes that exact automatic request using a
   purpose-specific action and current service identity. Human request/recovery
   remains current exact-project PM authority. An authorized source addition is
   durable consent; later PM revocation does not impersonate or revoke that
   original operation, while fixed-service authority must remain current.
4. Persist either trigger through the same request service/table and existing
   one-attempt uniqueness. Deterministic automatic operation/key identity is
   generation-bound. Duplicate callbacks recover the same request. SQL and Python
   verify matching origin/action/actor/digest/lineage; no human grant is invented.
5. Put human replay admission inside every existing and concurrent-recovery
   transaction, holding AUTH locks through receipt classification. AUTH closes
   fresh validation handles without minting another request decision event.
6. Prove both valid branches and targeted denials before focused review, then
   prepare one PR and wait for current-head hosted checks. Human owns merge.

## Acceptance and proof

- Automatic valid source-ready request creates exactly one immutable request and
  attempt under real fixed-service authority, with zero provider calls.
- Missing, foreign, stale or altered source operation/event, wrong actor/action,
  unready material, and incorrect digest deny with no request/attempt writes.
- Concurrent duplicate automatic requests preserve one operation/attempt/key.
- Direct forged automatic PostgreSQL inserts fail; valid controls reach the
  exact guard. Existing retained requests and finalizations remain immutable.
- Revocation-first human replay denies. Replay-first holds the actor/grant lock
  until classification completes. A mutation moving validation outside the
  transaction must be detected. Completed/uncertain recovery does not call a
  provider or enqueue anything in this hidden prerequisite.
- Existing manual request, compilation execution, projection and finalization
  contracts remain valid with exact current trigger evidence.
- Future manual correction stays a separately authorized new generation; no
  endpoint or service in this chunk manufactures one from a compilation retry.
