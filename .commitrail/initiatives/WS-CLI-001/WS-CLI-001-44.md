# WS-CLI-001-44 — Installable CLI release artifacts

- Initiative: WS-CLI-001
- Durable disposition: Planned
- Intended merge outcome: A reviewed, manually invoked GitHub Releases path builds and verifies installable CLI archives for four native platforms without publishing a release in this change.

## Intent

People and agents need an installable CLI without a Go toolchain. Issue #562 requires one channel, an explicit platform and version contract, exact-source artifacts, integrity metadata, and proof of installation and authenticated use. Distribution must not change CLI API authority or Workstream's unreleased backend claim.

## Current behavior

`cli/cmd/workstream/main.go` has a linker-set version and `cli/internal/command/command.go` exposes `--version`. `.github/workflows/cli.yml` builds a temporary Linux binary for public API tests, but publishes no artifact. `cli/README.md` correctly calls source build the only current path. No repository release tags exist at planning time.

- `.github/workflows/cli-release.yml` and scoped `.gitattributes`: native four-platform build/proof, LF package inputs and separately permissioned manual publication.
- `scripts/package_cli_release.py`, `scripts/test_cli_release.py`, `scripts/test_package_cli_release.py`, `scripts/test_cli_release_smoke.py`, `scripts/check_cli_release_controls.py`, `scripts/test_cli_release_controls.py`: deterministic packaging, manifest/control verification and installation smoke proof.

### Not allowed

No tag or release publication during implementation; no package managers, signing/notarization claim, TUI, new product commands, backend/auth/API changes, credentials, CI gate weakening, release of arbitrary pull-request code, or automatic publication on tag push. No compatibility promise for an unversioned server API.

## Design and decisions

The first CLI release channel is GitHub Releases. Stable tags use `cli-vMAJOR.MINOR.PATCH`; CLI `--version` contains `vMAJOR.MINOR.PATCH+gFULL_COMMIT_SHA`. This namespace separates CLI releases from backend/product v0.1. The initial supported matrix is Linux amd64, macOS amd64, macOS arm64 and Windows amd64. GitHub-hosted native runners prove each corresponding binary; Linux arm64 is not claimed. Unix archives are `.tar.gz`, Windows is `.zip`, each containing one executable and a license. A `SHA256SUMS` file binds every exact archive. Hashes detect accidental corruption or substitution relative to the trusted release page; they are not a signature.

The pull-request preview has read-only permission and runs all four native builds before a tag exists. A manual release run checks exact annotated tag object and peeled commit ancestry from protected `main`, verifies Go modules, builds with fixed Go version, CGO disabled, `-trimpath`, no VCS metadata or variable build ID, and packages normalized archives. Native smoke proof verifies the archive before clean installation, exact version, authenticated local API call without logging the token, simulated upgrade/rollback using a second local build, and removal. Those operations prove mechanics; first-release compatibility with a prior published version cannot be observed until a second release exists. Attempt-scoped artifacts prevent partial reruns from mixing native outputs; rerun all jobs for a fresh complete attempt. A separately gated publisher runs only for manual `workflow_dispatch` on the trusted default-branch workflow, rechecks all four archive identities and digests, and alone receives `contents: write`; it creates a draft release then publishes only after all assets are present and verified. A read-only dispatch-only guard and the publisher query GitHub's environment and repository ruleset APIs. They refuse missing or unverifiable human review, main-only branch policy or visible `cli-v*` tag update/deletion protection. GitHub hides ruleset bypass actors from the read-only workflow token, so an independent repository administrator must inspect and record the empty bypass list before approving the release environment. The `cli-release` environment and tag ruleset must be configured before a real run; workflow text and local tests cannot prove their hosted state.

Alternatives rejected: source-build CI is not installable distribution; package managers multiply unsupported channels; automatic tag-triggered publishing or a release token in a build matrix enlarges the privilege boundary; speculative signing/notarization lacks a managed key and owner decision.

## Acceptance criteria

- [ ] One tag/commit yields exactly four versioned platform archives and a checksum manifest; source and embedded version agree.
- [ ] Each platform's native runner verifies the installed archive, version, authenticated `whoami` over a local API fixture, upgrade/rollback mechanics and removal.
- [ ] A malformed tag, wrong source/ref, unsupported platform, missing/extra archive, or checksum mismatch fails before publication.
- [ ] Only the final manual publish job has release-write permission; it uses pinned actions, cannot accept untrusted PR-controlled release scripts and fails before publish on absent release-environment or immutable-tag controls.
- [ ] Installation, verification, API/server incompatibility diagnosis, platform limitations and macOS unsigned status are documented without credential disclosure.
- [ ] Existing CLI Go and public contract checks remain intact; no tag/release is published by this PR.
