## Design and decisions

Use an isolated database and uniquely owned runtime resources; run the built CLI against the real API, PostgreSQL, MinIO and durable Celery processing. Initial deployment bootstrap, schema migration, local test-token issuance and lifecycle deployment activation are explicit operator prerequisites, not hidden product-state seeding. Use provider-free manager-authored setup when supported; this proves that branch, not live model inference. Select a real locally executable registered checker; successful proof is bounded to its stated checks and runtime isolation.

Drive identity resolution and administrative grants, project/guide creation and original upload, explicit policy configuration and approvals, Finance publication, activation, task release, contributor claim/start, verified guide download, ZIP preparation/submission, checks and false-policy acceptance, then contribution export. Do not claim human-review completion or compensated fulfillment. Begin with explicit unpaid contribution rules because binding administration is not a public CLI operation.

Record exact source/binary identity and redacted stage results. Poll only observational reads; replay writes deliberately with unchanged keys and inputs. Read-only database observations may corroborate atomicity but cannot create the facts being proved. Reconcile newly merged CLI commands and repeat affected proof before final readiness claims.
