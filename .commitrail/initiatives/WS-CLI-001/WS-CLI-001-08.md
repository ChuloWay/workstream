# WS-CLI-001-08 — Create a draft project shell

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: Create a project shell through the existing public
  REST operation, preserving explicit replay custody and uncertain outcomes.

## Intent

Inspection and contributor preparation are delivered. Begin the already
proposed project-setup journey with `POST /api/v1/projects`, publicly registered
by `projects/create_router.py`. `ProjectCreateService` owns system-scoped
Project Manager authorization, server-generated identity, transaction and
actor/action/key/body replay. The result is a project shell, not an approved
guide or claimable work. No backend implementation or permission is added.

## Bounded change

Allowed: `cli/internal/api/project_create.go`, `project.go`, `client.go` and
`task_mutations.go`; `cli/internal/command/project_create.go` and `command.go`;
`cli/tests/integration/test_project_create_http.py`, `project_create_journey.py`
and `test_public_self_service.py`; CLI/root README, affected roadmap claims,
this record, overview and index. No backend, MCP, workflow/dependency, hidden
route, guide creation/upload/activation, grants, local authority/policy engine,
credential persistence, preflight, generated key, automatic retry or TUI work.

Add `workstream project create --name TEXT --slug TEXT --idempotency-key UUID
[--description TEXT]`. Require both flags, including explicit empty values
where accepted by the API. Validate UTF-8, NUL exclusion and the backend's
200/120-character name/slug bounds. Preserve supplied text, whitespace and
description omission versus explicit empty. Reuse the existing 8KiB encoded
request bound; description has no additional character ceiling. Send exactly
one fixed POST, with unchanged bearer/key and no request preflight.

Extend the existing private transport with a caller-selected expected success
status: existing operations retain 200, creation requires 201. Never accept an
arbitrary 2xx as success. Preserve one-shot mutation bodies, redirect/proxy
refusal, deadlines, response bounds and credential-safe errors. Reuse the
canonical POST error validator for project creation, naming it for its shared
mutation responsibility rather than copying a task-specific implementation.
Do not alter the profile PATCH error contract.

Share project response parsing/output with `project show`. Creation requires
the complete seven-field administrative ProjectResponse, valid UUID/timestamps,
nullable description and no unknown/duplicate/null required fields. It cannot
bind a returned ID to a nonexistent input selector. Preserve the exact raw JSON
and show all seven fields safely. Do not require every replay to say `draft`:
the backend recovers the current stored project, which may have progressed.

Lost, malformed, oversized, redirected, unexpected-status and noncanonical
responses are unknown mutation outcomes. Only a complete canonical 4xx proves
a known denial. Text recovery guidance retains the same name/slug/description
and key; it must not invent a project ID, promise rollback or suggest a new key.
Existing project-create replay deliberately recovers a committed result after
creation-grant revocation (`test_project_create_exact_replay_and_mismatch_are_atomic`).
Do not impose TASK's different replay semantics in the client or claim that
recovery authorizes another creation. Fresh creation still requires authority.

## Acceptance criteria

- Named built-process HTTP cases prove one POST and exact 201 response, all
  request fields, key spellings, omission/empty description, accepted text
  boundaries, complete escaped text/raw JSON, and invalid input without network.
- Reject minimal GET-only projection, malformed UUID/time/required field,
  unknown/duplicate members, null/wrong-type description and unexpected 200/202.
  Exercise known canonical 4xx versus malformed envelope, including null
  details, dropped response, redirect and oversized reply; stdout stays empty.
- A real TLS/HTTP2 GOAWAY case proves exactly one transmitted creation body
  and an unknown outcome. Simulated rewindable-body variant must fail that case.
- Extend the existing one-bootstrap public FastAPI/PostgreSQL journey via
  `project_create_journey.py`, not a second parallel fixture. Assert OpenAPI
  exposure, persisted creation/direct-GET parity, exact manual replay and body
  mismatch; slug collision is a server conflict, not an overwrite. No private
  product writes or fake authorization. Prove a project-scoped manager and
  absent/Access Administrator-only authority cannot create; use public grants
  and fresh-key creation controls to prove revocation and suspension denial.
  Preserve existing read/task tests and backend-owned replay semantics.
- Go build/vet/verify/tidy-diff; Ruff/format; complete CLI process/API suite;
  unchanged workflow guards; links/stale scans/Commitrail and full hosted
  Backend remain required. No coverage/count quotas or weakened selection.

## Risk and review routing

Risk `L1`: shared status handling, duplicate creation after lost responses,
bearer leakage and false authority/recovery claims. Plan feasibility review
before code; three focused assignments for architecture/docs, security and
QA/test-delta. Shared transport proof must retain all existing command behavior.
Lead owns deterministic checks and hosted monitoring, not nine reviewer runs.
Human focus: exact 201, caller-owned key, project shell versus guide readiness,
and replay recovery versus authority for a fresh write.
