# WS-CLI-001-22 — Inspect contribution-policy selectors and versions

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: Finance Authorities discover current policy selectors and inspect exact retained policy versions through public REST reads.

## Intent

Complete policy inspection before adding Finance editing/publication commands.
`project contribution-policy current PROJECT_ID` recovers the current aggregate,
published version and open draft. `project contribution-policy show PROJECT_ID
POLICY_ID [--version UUID]` inspects the owner's selected version or one explicit
historical version. Observations do not grant write authority or prove readiness.

## Current behavior

CLI01–21 cover 32 documented public command surfaces through merged #545.
`backend/app/api/routes/contribution_policies.py` already exposes public GET
`.../contribution-policies/current` and `.../contribution-policies/{policy_id}`,
with optional `version_id`. The CON service/repository own default selection and
exact project/policy/version scoping; current discovery excludes retired
aggregates. Exact retired versions remain readable with current Finance
Authority. Project Manager authority alone does not authorize these operations.
Guide activation is a separate manager action binding an exact published version.

## Design and decisions

Use existing closed/null-aware JSON parsing, UUID identity, finite JSON transport,
decoded credential protection and complete escaped text/raw JSON output. Preserve
the original path/query UUID spelling. Current selector response has four fields;
both version selectors are nullable, but a successful selection cannot have
both null or the same normalized UUID in both roles. Version response retains
complete rules and
definitions, including Finance binding identifiers and exact string quantities,
without treating an incomplete draft or historical version as ready. Reuse scalar
award wire validation; do not copy backend publication/compensation business rules.
Default show is explicitly backend-selected; an explicit --version must bind the
returned version. No preflight, auto-current fetch or cached selectors.

## Acceptance criteria

- One public current or show GET; optional `version_id` is forwarded only when
  requested. Invalid selectors/empty explicit version fail without HTTP.
- Complete text/JSON projection for empty draft, unpaid rules, compensated
  definitions and both nullable current selectors. Quantities retain exact text;
  floats, null members, duplicate/unknown/missing fields and malformed identities
  do not become successful facts. Unique normalized rule/definition identities,
  closed role/instrument tokens and exact requested project/policy/version hold.
  Policy status is `draft|active|retired`; version status is
  `draft|published|retired`. Preserve independently valid historical combinations,
  not a local readiness matrix. `version_number` is a present positive integer
  using the existing `big.Int` JSON pattern, without machine-integer narrowing.
- Otherwise-valid current responses with both nullable selectors null, or the
  same UUID under alternate spellings in both selectors, fail. Both one-null
  variants and distinct both-present selectors remain valid. Invalid/missing/null
  status/version facts fail after positive controls; oversized positive integers
  retain exact JSON/text instead of overflowing the client.
- Valid controls precede otherwise-valid foreign project/policy/version replies,
  normalized duplicate IDs, malformed nested definitions and credential reflection.
  Every invalid read leaves stdout empty; it is not an unknown write outcome.
- Extend existing real public-socket/Flow/PREP/PostgreSQL guide activation proof,
  not a second broad daemon fixture. Public setup exposes the existing unpaid
  policy's empty draft, published graph, simultaneous published/open-draft
  selectors and historical retirement. PM-only, other callers, a stored foreign
  policy/version and a foreign-project Finance actor are denied. Suspend/reactivate
  and revoke/restore Finance authority through existing public admin setup;
  positive controls precede denials. Existing activation/replay/retirement checks
  remain intact. Read snapshots cover all CON policy tables/lifecycle events,
  excluding legitimate AUTH read evidence. Reads do not publish/edit/activate.
- Compensated quantity precision is process-boundary proof, not a new native
  compensated-policy or fulfillment certification. Existing backend economics
  tests remain hosted; no payout or readiness claim is made by this client.
- A target-binding or duplicate-normalization mutant must fail the specific
  regression after its valid control. Full hosted execution remains blocking.
