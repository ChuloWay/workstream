# WS-CLI-001-26 — Edit draft guides and configure review/revision policies

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: Public Go CLI commands for issue #599's existing guide PATCH and review/revision policy PUT operations.

## Intent

Project managers can declare and inspect a guide in the CLI, but cannot yet edit
its draft summary or set its two guide-bound policies without another HTTP client.
Expose `project guide edit PROJECT_ID GUIDE_ID --input FILE --idempotency-key UUID`,
`project guide set-review-policy PROJECT_ID GUIDE_ID --input FILE --if-match ETAG --idempotency-key UUID`,
and `project guide set-revision-policy` with the same selectors/flags. These are
deliberate public writes, not guide approval or activation. The server owns
current authority, draft guards, replay, optimistic selection, immutable policy
lineage and all lifecycle decisions. A prior read does not authorize a write.

## Bounded change

Allowed: new `cli/internal/api/guide_config.go`,
`cli/internal/command/guide_config.go`, registration in existing
`cli/internal/command/guide_create.go`, a bounded fixed-header extension of
`cli/internal/api/client.go`, focused built-process and real-API tests under
`cli/tests/integration/`, `cli/README.md`, affected `docs/roadmap_status.md`
claims, this record and the scoped `WS-CLI-001/OVERVIEW.md` current-boundary
claim coordinated with the CLI lead. The lead owns index reconciliation.
`cli/internal/command/command.go` is not currently needed.

Prohibited: backend/schema/database/CI/dependency changes, private API or SQL in
the shipped CLI, new routes, generated keys, implicit latest-policy lookup,
refetch-and-overwrite after stale preconditions, automatic mutation retry,
parallel old/new commands, TUI or release packaging. Do not alter existing
guide creation, upload, approval or activation behavior.

## Acceptance criteria

1. Reuse the existing `project guide` Cobra owner, bounded regular JSON-file
   reader, UUID identity, JSON/text output and one-shot bearer transport.
   Accept only closed public request fields and preserve source bytes, omission
   versus explicit null, supported booleans and exact JSON integer values. Bound
   file and reply sizes; reject malformed/duplicate/unknown fields locally.
   Leave semantic policy admissibility to the backend, including its numeric
   and lifecycle rules; the CLI must not narrow valid backend integer range.
2. PATCH forwards the exact caller key and body; PUT forwards the exact caller
   key, body and explicitly supplied `If-Match` (initially
   `"no-current-policy"`, thereafter the exact selected-policy ETag). Pass a
   bounded, control-free header value without narrowing backend-supported UUID
   selector spellings or deriving it from a read. Do not retry a
   conflict. Canonical known 4xx denials stay known; drops, ambiguous errors and
   malformed success are uncertain, with unchanged-input/key/precondition
   manual-recovery guidance.
3. Validate complete success responses before output: exact project and guide
   UUID identity for PATCH; guide draft state and requested summary; policy
   project identity, version/ID/hash/generation, selected predecessor and
   request-explicit values for PUT. Preserve full numeric values and reject
   missing, contradictory, foreign or malformed receipts. Text rendering must
   escape terminal controls; JSON mode exposes complete validated public JSON.
4. Built-binary HTTP tests cover exact method/path/header/body, omitted/null
   fields, large numeric values, malformed/mismatched responses, local refusal
   without network, canonical denial, replay conflict, stale precondition and
   unknown write with no transport replay. A real FastAPI/PostgreSQL journey
   proves successful writes and reads, fresh manager authority, denied/foreign/
   revoked authority, changed-input replay and stale selection. Existing CLI
   commands remain functional; no real S3 proof is needed because no bytes or
   custody are claimed.

or lifecycle authority. One PR; never merge without specific human approval.
