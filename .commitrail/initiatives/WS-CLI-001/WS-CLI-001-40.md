# WS-CLI-001-40 — Inspect and reconcile uncertain post-submit deliveries

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: A covered system Operator can inspect one bounded project page of exact UNKNOWN post-submit deliveries and deliberately reconcile one selected event through the existing public API without local recovery decisions or automatic retry.

## Intent

[Issue #634](https://github.com/Flow-Research/workstream/issues/634) closes the two-route CLI gap created by the supported public delivery-reconciliation owner. Discovery is observation only; an explicit, independently authorized write uses the caller's reason and UUID replay key. This is separate from known-terminal checker retry and from blocked artifact-operator issue #611.

## Current behavior

`backend/app/modules/checkers/router.py` publishes project-scoped GET `/operations/projects/{project_id}/post-submit-deliveries` and POST `.../{event_id}/reconcile` under `/api/v1`. `PostSubmitDeliveryPage`, `PostSubmitDeliverySource`, and `PostSubmitDeliveryResult` in `backend/app/modules/checkers/api/delivery_reconciliation.py` bind project, source event, classification, immutable child and decision. `backend/app/modules/authorization/catalogue.py` marks both exact actions active; production `post_submit_delivery_service` composes the AUTH read and write adapters. `backend/tests/checkers/execution/test_delivery_reconciliation_public.py` proves owner-produced UNKNOWN source, authorized discovery, one child, replay and denial on PostgreSQL. The CLI's existing `operations checker` group covers a different terminal-failure workflow; it has no delivery commands.

## Bounded change

Allowed: new `cli/internal/api/post_submit_delivery.go` and `cli/internal/command/post_submit_delivery.go`, one registration call in `cli/internal/command/command.go`, focused built-binary HTTP and signed real public API/PostgreSQL tests under `cli/tests/integration/`, this record, and affected `cli/README.md` and `docs/roadmap_status.md` claims. The CLI lead owns initiative overview/index navigation.

Prohibited: backend, AUTH, CHECKERS, OUTBOX, database, provider, CI, dependency or shared HTTP-client changes; local classification/eligibility or authority decisions; automatic read-before-write, child dispatch, retry, silent replay, checker-retry alteration, TUI, release packaging or compatibility command.

Add `operations delivery list PROJECT_ID [--limit N] [--cursor TOKEN]` and `operations delivery reconcile PROJECT_ID EVENT_ID --reason TEXT --idempotency-key UUID`. Reuse the existing one-origin bearer client, bounded JSON response, safe terminal output, UUID/cursor helpers and one-shot POST transport. Validate exact page project, bounded unique source event identities and full response shape; preserve generation integers without float rounding. Validate a reconciliation receipt's selected project/event, source-child lineage and backend's conditional classification/state relationship, without requiring only pending state on replay. The CLI never treats a read as permission for a write. On an unknown POST outcome, advise only deliberate replay of the unchanged project, event, reason and key.

## Acceptance criteria

- Exact authorized GET query and one explicit keyed POST; malformed selector, cursor, reason or key fails before HTTP; no automatic retry or provider access.
- Bounded, credential-safe JSON/text output; malformed, foreign, crossed, duplicate, oversized or control-bearing success responses fail closed. Unknown writes never present success or claim rollback.
- Built-binary process tests cover wire shape, pagination, lineage, denials, malformed results, no retry and credential safety. A signed public API/PostgreSQL journey uses owner-produced UNKNOWN evidence and proves CLI discovery, reconciliation, exact replay and fresh denial after authority loss; it claims neither a hosted interruption drill nor S3 custody.
- Existing checker retry and other CLI commands remain unchanged; current roadmap and CLI docs distinguish the two recovery workflows.

## Risk and review routing

L1: the write can initiate one immutable recovery child with governed downstream effects. Security checks selector binding, fresh authority, redaction and one-shot transport; QA/test-delta check malformed success, replay and denial proof; product-ops checks observation versus deliberate reconciliation; architecture/reuse/docs check the public-port boundary, one operations root and precise capability wording. Human review focuses on exact project/event/child identity, no locally inferred safe retry, and honest unknown-outcome/manual replay behavior. The CLI lead coordinates frozen-head review and native test slot.
