# WS-CLI-001-29 — Explicit Operator checker registration and recovery

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: The Go CLI exposes the four already-public external-checker registry and terminal checker-retry operations from [issue #608](https://github.com/Flow-Research/workstream/issues/608), without transferring authority or lifecycle decisions from the backend.

## Intent

Operators need an explicit public client for immutable digest-pinned checker registration/read and known-terminal post-submit infrastructure retry. The backend already owns fresh authorization, exact project/source eligibility, registration immutability, reason-bound replay, audit and successor custody. This change sends selected inputs and displays verified public responses; registry publication does not enable execution, and a source-list read never authorizes a later retry.

## Bounded change

Allowed: new cohesive `cli/internal/api/checker_operations.go` and `cli/internal/command/checker_operations.go`; one explicit `operations` root construction at the `cli/internal/command/command.go` composition root, checker child registration there, and the terminal-safe JSON output fix; focused built-binary HTTP and real-API/PostgreSQL tests under `cli/tests/integration/`; `cli/README.md`, affected `docs/roadmap_status.md` claims, this record, and the lead-provided `.commitrail/INDEX.md` row correction. Reuse the existing `guide_post_policy.go` checker schema validator without changing its POST policy contract. Existing shared CLI API/client and validation helpers may otherwise be changed only if a concrete contract requires it, with CLI-lead coordination first. The initiative overview and other index rows are lead-owned.

Not allowed: backend endpoints, schemas, storage, authority or worker changes; CI weakening; private imports or SQL in shipped CLI; automatic mutation retry, preflight authority check, hidden checker selection, local execution enablement, TUI, packaging, compatibility paths or merge. Existing commands and their helpers retain behavior.

## Plan

1. Add `operations checker registry register --input FILE --idempotency-key UUID` and `operations checker registry read ENTRY_ID` for the exact `/api/v1/operations/external-checker-registry` public contracts. Validate a closed input including phase-specific protocol schema identities, digest-pinned image, schema document objects/hash formats and bounded resources; preserve the selected bytes/key and require a closed entry response bound to the submitted immutable spec/key or read selector. The backend alone computes canonical JSON/schema and entry digests; the CLI does not implement a rival canonicalizer. No local capability or image selection.
2. Add `operations checker retry-sources PROJECT_ID [--limit N] [--cursor TOKEN]` and `operations checker retry PROJECT_ID SOURCE_RUN_ID --reason TEXT --idempotency-key UUID`. Validate the bounded project page and source/successor identities, exact selector binding, recovery-state closure and immutable receipt/replay key; leave eligibility and current authority with the backend. One explicit POST only; report uncertain write outcomes with an exact manual-replay hint.
3. Document exact commands, schema input and replay semantics in CLI README; reconcile only affected roadmap status claims, keeping merged backend capability distinct from CLI exposure and deployment.
4. Prove built-binary request/path/header/body fidelity, safe output, malformed/foreign response rejection, denial, replay and no-auto-retry. Exercise a real API/PostgreSQL Operator journey (including fresh authority and an ineligible/foreign source control) through the built binary. Run Go build/vet/module verification, focused and complete CLI checks, stale-wording/link checks. No S3 claim is made by this CLI slice.
5. Resolve frozen-candidate review findings before readiness: close retry source/successor generation and identity lineage on receipts and historical retried pages; compare schema JSON numbers against backend/PostgreSQL normalization without losing large-integer precision; reuse the existing external-checker schema validator; and escape U+2028/U+2029 in shared machine-readable output. Add focused regressions and a persisted replay proof, then refresh exact-head evidence and affected reviews.
6. Keep `operations` a single explicit composition-root namespace so this checker child and independently owned Operator task commands can register without duplicate roots. This only relocates root construction; it adds no generic command factory or task behavior.

## Acceptance criteria

- All four existing public endpoints are reachable through the documented commands, with exact selected fields/keys, bounded responses and machine-readable output.
- Built-binary HTTP proof covers request/response fidelity, malformed and foreign replies, denial, replay and no automatic retry; a real signed API/PostgreSQL journey checks fresh Operator authority and retained effects.
- Existing commands remain distinct and unchanged; registration does not enable execution and the CLI does not decide retry eligibility.
- Retry responses close source/successor lineage; equivalent numeric schema documents remain valid after PostgreSQL normalization while non-equivalent large integers do not; JSON output retains one safe terminal line per response.
