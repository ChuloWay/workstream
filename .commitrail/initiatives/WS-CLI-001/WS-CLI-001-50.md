# WS-CLI-001-50 — Readable contributor terminal workbench

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: Replace the contributor TUI presentation in place with visible navigation, readable work content and truthful evidence states.

## Intent

The human's 26 October design brief targets main `fcd32057`, which still matches
the inspected implementation. Existing contributor reads and verified downloads
work, but hidden tabs and flat metadata streams make instructions hard to find.
This is a presentation redesign, not the separate fixture prototype or a new
product capability. No overlapping production TUI PR was found during discovery.

## Bounded change

Allowed: `cli/internal/tui/`, focused existing `cli/tests/integration/test_tui*`
and native terminal observer support, `cli/README.md`,
`docs/design/cli-terminal-experience.md`, affected `docs/roadmap_status.md` claims,
and this initiative's records. Command terminal-capability plumbing may change
only if necessary for existing Bubble Tea background detection; no new config.

Replace view composition with a measured shell, visible collection/section labels,
contextual footer, loaded-page observation line, and two panes only at >=100x24.
The right viewport owns scrolling while the retained left list preserves exact
selection. Plain mode stays single-column. A small style owner supplies semantic
slate/cyan/peach and readable light-terminal equivalents without dependencies.
Group existing detail values by the brief's reading order, retaining all exact
IDs, hashes and decimal strings. Uninspected previews use only loaded row facts.

Keep the existing model, typed requests, generation/cancellation and staged
download owners. Reflow changes no selection and dispatches no request. A narrow
prose sanitizer may preserve LF paragraph boundaries after bearer suppression,
while escaping all other controls and keeping labels/IDs on the existing strict
sanitizer. Long confirmation content must remain scrollable without changing
the explicit destination -> Enter -> y publication decision.
Entering confirmation resets its viewport to the target heading. Existing scroll
keys can inspect its remaining fields; below 40x10, `y` cannot stage files or
dispatch a download while only resize guidance is visible. The retained worklist
is composed outside the scrolling detail viewport.

Prohibited: backend/API/client changes, new product mutations, polling, stale
caches, manager/review workspaces, credentials, shell execution, automatic viewers,
clipboard, new dependencies, release/CI weakening, compatibility implementations.
The existing design document becomes the single current presentation contract.

## Acceptance criteria

- Mine Overview at 120x40 and 80x24 prioritizes complete instructions and criteria;
  terms remain potential, exact and separate for submission/review contributions.
- Collection and applicable section labels stay visible with one active label.
  Resize and Unicode wrapping remain cell-bounded at 40x10 and above; below that
  retain resize/quit guidance. Plain/no-color and light terminals remain readable.
- Row movement makes no requests; Enter performs the existing exact fresh read.
  Findings/list continuations remain distinct one-page requests. Late responses,
  denial and unavailable sessions cannot restore protected content.
- Guide metadata is not called verified until a successful verified download.
  Confirmation includes exact target/destination/bytes/hash and explicit y;
  cancellation, no-overwrite and cleanup behavior are unchanged.
  A confirmation resized below minimum cannot dispatch or stage on `y`; restoring
  size preserves its exact target and still requires deliberate confirmation.
- Stored outcomes are distinguished from findings; no inferred payment, authority,
  acceptance or progress. Inert CLI arguments and explicit CLI contracts remain.
- Representative fixture terminal renders cover picker, lists, task/intake/guide,
  submission/findings, empty/filter miss/denial/help at desktop, compact and plain
  sizes. Render evidence is not live-backend evidence.

## Risk and review routing

L1: presentation of untrusted terminal text and exact download confirmations.
Plan review before implementation; final focused security, QA/test-delta,
architecture/reuse and documentation review on a clean pinned candidate.
No authorization policy or custody operation changes are authorized.

The cohesive diff exceeds the preferred small-change line budget: the existing
detail renderer moves out of view.go while being regrouped, the obsolete mixed
current/future design document is replaced, and presentation/terminal regressions
cover the shared shell across existing screens. Splitting would leave competing
renderers or inconsistent navigation. Requests, API, download custody, dependencies
and workflows are unchanged; focused reviewers inspect these separate risks.

## Human review focus

## Evidence

Discovery inspected existing view/model/request boundaries and current tests;
baseline and brief match. Plan review identified hidden confirmation after resize.
`TestHiddenConfirmationCannotStageOrDispatch` failed on the pre-fix owner because
`y` staged a download while only resize guidance was visible, then passed after
the size guard. The same test restores the exact confirmation and verifies the
deliberate positive publication. A native terminal regression covers this boundary.

The old flat Guide assertion is replaced by server-order rows plus exact selected
metadata before and after selection. Finding assertions retain every prior value
in the new grouping. Native resize proof scrolls to exact references and back to
instructions rather than requiring both to occupy the initial viewport. No test
is removed or skipped. Representative renders are fixtures, not live product
proof; native socket and signed-API/PostgreSQL journeys remain distinct checks.
