# WS-CLI-001-19 — Manager task preparation

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Managers create a draft task, screen its locked guide/policy context, and deliberately release it through existing public APIs.

## Intent

Guide activation and contributor claim/start are available in the CLI, but a
manager still needs REST to prepare individual tasks. Add three deliberate
commands under the existing `project task` command:

```sh
workstream project task create PROJECT_ID --input FILE --idempotency-key UUID
workstream project task screen PROJECT_ID TASK_ID --idempotency-key UUID [--reason TEXT]
workstream project task release PROJECT_ID TASK_ID --idempotency-key UUID --reason TEXT
```

Each invocation issues exactly one public POST. Creation forwards the original
closed `TaskCreate` JSON; screening/release use the existing transition body
and keyed no-replay transport. Preserve optional/null semantics. The create
route requires a canonical project UUID; accept only that spelling there rather
than claiming alternate spellings the route rejects. Transition selectors retain
their supplied supported spelling. No automatic sequence, preflight read,
local authority, guide selection, validation of business readiness or retry.
Backend owners retain fresh authority, active guide selection, locked lineage,
state transitions, immutable replay receipts and transaction/audit atomicity.

Validate the complete public management `TaskResponse`, including task/project
identity, exact action status and retained lineage. A draft has no locked
policy lineage; screening/release require the backend's complete locked fields.
Creation compares echoed declaration fields with supplied values and public
defaults, without requiring the new task ID in the request. JSON output retains
the authorized response; text is escaped. Suppress credential reflection in
decoded response fields. A malformed or substituted successful write is an
unknown outcome, never success; recovery is deliberate unchanged-input/key
replay, not a new key or locally inferred rollback.

Receipt binding compares import-batch identifiers as nullable text, not record
UUIDs. CLI deadlines use RFC3339 and compare instants at the backend's
microsecond precision, permitting timezone normalization without accepting a
different deadline. A malformed input timestamp fails before HTTP. The native
blank-release control asserts the owner's canonical 422 validation response.

disable idle connection pooling for that test's direct comparison client
without adding retries or changing CLI transport;
README, CLI README, affected roadmap entries, this record, overview and index.

Prohibited: backend, migrations, AUTH policies, dependencies/workflows, hidden
submission routes, bulk import, operator overrides, Finance operations, automatic

Do not expose source custody through contributor responses or enlarge their
existing response decoder. A backend prerequisite defect requires a reproducer
and diagnosis, not a permissive fake or copied policy engine.

Rejected: an endpoint-generated command catalogue and a create-and-release
shortcut; explicit operations preserve the manager's decisions and replay keys.

## Acceptance criteria

- Built process sends exact public path/bearer/key/body once. Creation is 201;
  screen/release are 200. Invalid shapes, duplicate/unknown fields, invalid
  selectors/keys and oversized input fail before HTTP. Reason omission/empty
  remain distinct; the backend decides whether a reason permits release.
- Closed full response rejects wrong project/task/status, malformed identities,
  missing/null required values, unknown fields, malformed arrays, invalid times,
  partial lineage and changed creation fields. Valid control precedes each
  malformed/substitution proof. Draft absence differs from screened lineage.
- Credential/terminal safety, canonical denial versus unknown outcome, bounded
  transport and one HTTP/2 POST retain the canonical owner proof. New operations
  get action-specific process cases, without duplicating every transport test.
- Extend the existing production socket/Flow/PREP/PostgreSQL journey instead of
  paying for another database/server bootstrap: public CLI creates/screens/
  releases a real task under approved canonical guide prerequisites. Exact REST
  replay matches CLI output; stored task, locked policy and audit facts match.
  Changed input/key rejects, foreign-project grants deny, suspended/revoked
  managers cannot replay, and contributor-only authority cannot prepare tasks.
  Existing contributor discovery/claim/start proves the released task usable.
- Countercheck: an otherwise-valid foreign project receipt must fail the named
  response test when only project binding is removed. Source fixtures are not
  live inference or deployed Flow certification; unchanged backend concurrency
  proof remains hosted, not inferred from a sequential CLI journey.
