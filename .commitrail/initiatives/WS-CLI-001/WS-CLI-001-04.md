# WS-CLI-001-04 — Browse project tasks as a manager

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Browse one project's management queue and inspect a
  selected task through existing public REST reads.

## Intent

Continue the Go CLI after project inspection. Give a project manager a coherent
list-to-detail journey, without inventing contributor intake or local authority.

## Current behavior

`queue_router.py:management_tasks` exposes `GET /api/v1/projects/{project_id}/tasks`
with a 1–100 item limit and an opaque, action/project/limit-scoped continuation.
`router.py:get_management_task` exposes the corresponding project/task detail.
AUTH authorizes each read; TASK owns summary/detail projections. Draft tasks
can be created through the public manager POST without activated guide context.
The CLI has project inspection but neither read.

## Bounded change

### Allowed

- Cohesive task-read client/command files under `cli/internal/`, reusing current
  transport, UUID identity, strict JSON validation and terminal escaping.
- Built-executable integration proof under `cli/tests/integration/`.
- CLI/root README, affected roadmap claims, this record, overview and index.

### Not allowed

- Backend/MCP/workflows/dependencies, hidden routes, task writes, claim/start,
  automatic retries or pagination, role inference, credential persistence,
  generic dispatch, TUI, or another test/coverage gate.

## Design and decisions

`project tasks PROJECT_ID [--limit 50] [--cursor CURSOR]` makes one management
queue GET. `project task PROJECT_ID TASK_ID` makes one detail GET. Escape UUID
selectors as individual path segments and compare returned identities by UUID
value. Limit and cursor are encoded query values, never URLs. Validate local
limit 1–100 and cursor at most 512 Unicode characters; forward it unchanged and
leave verification to the server. Empty supplied cursor is invalid.

Require the complete queue envelope and required summary fields, non-null item
and tag arrays, valid identities/timestamps and correct project ownership.
Reject unknown/duplicate fields and malformed detail, including a substituted
task ID. Detail nullable fields may be omitted because the public route uses
`response_model_exclude_none`; accept explicit null for those same fields.
Preserve successful JSON. Render complete documented task fields safely in
text, including the opaque continuation. A cursor is not authority/reservation;
each page reauthorizes, with no preflight or client-side filtering. Existing
64 KiB response bound remains; oversized pages fail with no partial output,
and callers can choose a smaller limit. Do not follow links from responses.

## Acceptance criteria

- [ ] Exactly one fixed public GET per command, original escaped UUID selectors
  and unchanged bearer; bounded encoded pagination, invalid inputs make no call.
- [ ] Text and raw JSON preserve documented fields, null/omission semantics and
  continuation; terminal controls cannot execute.
- [ ] Invalid envelope/item/detail, null required data, unknown/duplicate keys,
  foreign project/task identities and oversized replies cannot report success.
- [ ] Real API/PostgreSQL creates two projects and draft tasks through public
  routes; page one and two use limit=1 and match direct API responses. The same
  cursor with a different limit returns 422. A system manager authorized on
  both projects reusing A's cursor on B receives 422, not an authority denial.
- [ ] An exact-project-A manager receives concealed denial on stored project B
  before cursor parsing. Revoke that actor's exact manager grant and prove both
  reads denied; reissue a fresh exact grant and prove both reads succeed before
  suspending that same actor and proving both reads denied again. All CLI calls
  must appear in OpenAPI; bootstrap is fixture-only.
- [ ] Existing CLI tests remain intact; build/vet/dependency/doc/process checks
  and complete hosted CI pass. Docs distinguish source availability from release.

## Risk and review routing
