# WS-CLI-001-21 — Inspect project contributor grants

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Managers inspect one filtered project-grant page or one exact grant and its qualification history through public AUTH reads.

## Intent

After explicit issuance/revocation, a manager needs to inspect retained decisions
without keeping an old mutation receipt. Add `project role-grant list PROJECT_ID`
and `project role-grant show PROJECT_ID GRANT_ID`. These are observations, not
authority tokens, eligibility decisions or rollback proof.

## Current behavior

CLI20 supplies explicit issue/revoke. AUTH already exposes public GET collection
and detail in `backend/app/modules/authorization/router.py`; `read_service.py`
requires fresh covered Project Manager or Audit Authority before cursor resolution or stored-row
lookup. `schemas.py` defines complete qualification and revocation projections.
Collection filters are status, role, limit 1–100 and an opaque cursor <=512
characters. No count, snapshot membership or automatic paging is promised.

## Bounded change

Allowed: new `cli/internal/api/project_role_reads.go`; extend the existing
qualification validator in `project_role_mutations.go` without changing write
semantics; extend command registration in `project_role_mutations.go`; new
`cli/tests/integration/test_project_role_reads.py`, small read helper in
`project_role_read_journey.py`, and calls from existing `project_role_journey.py`;
README, CLI README, affected roadmap claims, this record, overview and index.
The shared denial metadata owner `cli/internal/api/client.go` also receives the
scoped UUID-identity credential-reflection repair reproduced on these reads;
transport, deadlines and other response contracts remain unchanged.

Prohibited: backend/schema/migrations, dependencies, CI budgets or selection,
actor discovery, AdminRole management, local authority/qualification scoring,
automatic pagination, grant writes beyond existing commands, hidden submission,
bulk-task work owned separately, unit-test suites or percentage gates.

## Design and decisions

Reuse the existing role-grant command group, transport, closed/null-aware JSON
decoder, UUID identity and qualification validation, cursor wire checks and
escaped output. Validate complete nested receipts, exact requested project/grant,
filter consistency and normalized duplicate identities. Preserve the response
JSON unchanged. A bounded 2 MiB read accommodates up to 100 qualification-bearing
records; the request deadline remains 12 seconds. Reuse decoded credential
reflection safety. Never turn a successful page into current write authority.
No generic administration framework or duplicated qualification rules.

## Acceptance criteria

- List makes one public GET with explicit limit, optional status/role and an
  opaque unchanged cursor; show makes one exact public GET. Supported UUID
  spellings remain on the wire, while response binding uses UUID identity.
- Empty and multi-row pages, active/revoked rows and complete qualification/
  provenance survive text/JSON output. No automatic continuation or hidden fields.
- Invalid selectors/filters and empty, over-512-character or invalid-UTF-8
  cursor strings fail without HTTP. Forged or query-mismatched opaque cursors
  make one GET and preserve the backend's canonical invalid-cursor denial;
  the CLI never verifies their signature or interprets their contents. Malformed, unknown,
  missing/null required fields, substituted project/grant, contradictory filter
  results, normalized duplicate IDs, invalid nested qualification and credential
  reflection leave stdout empty and never report success.
- Real public API/PostgreSQL journey compares reads with public responses and
  retained grant/snapshot facts after issue and revoke. Stored foreign grants,
  contributor-only callers, suspended or revoked managers are denied. Reusing a
  cursor after manager revocation does not retain authority; changed filters
  refuse cursor reuse. Reads add no grant/snapshot mutation or role audit events.
- Regressions contain a valid control and a discriminating project-binding or
  duplicate-normalization defect probe. Existing claim/start and write/replay
  assertions remain intact; full hosted collection remains blocking.
