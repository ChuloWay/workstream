# WS-CLI-001-17 — Guide correction and explicit successor dispatch

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: Managers save an exact proposal correction and explicitly dispatch its retained successor through existing public APIs.

## Intent

Add `project guide correct PROJECT_ID GUIDE_ID COMPILATION_ID --input FILE
--idempotency-key UUID`, posting the original closed `{target, reason}` input
once to the public proposal `/corrections` operation. Reuse proposal-target
validation and the existing correction receipt schema. Require RFC UUIDv7
receipt identities, valid digests and the submitted generation plus one using
arbitrary-range integers. Digest computation and feedback normalization remain
backend-owned. Saving does not enqueue, approve or activate.

Add `project guide dispatch-correction PROJECT_ID GUIDE_ID COMPILATION_ID
--input FILE`. The file contains the exact saved `GuideProposalCorrectionReceipt`
(the whole `correct` JSON output, or the `correction` member from `correct-post`).
Its operation ID selects the existing public bodyless `/corrections/{id}/dispatch`
POST; no invented request body or caller idempotency key. Validate the four-field
202 response against that receipt's operation ID, successor ID and generation.
The backend owns fresh scoped authority, request custody and delivery recovery.
Preserve its open diagnostic status, including `enqueue_failed`; a valid response
observes dispatch status, not completed processing, approval or activation.
Never automatically retry or fetch a latest target. Ambiguous writes emit no
success and explain manual recovery using the unchanged input and selectors.

Prevent transport replay for zero-byte POSTs as well as existing nonempty
writes: use a non-rewindable empty reader, not a fabricated JSON payload.
Reuse the HTTP/2 GOAWAY fixture, retaining every existing nonempty-body assertion.

## Acceptance criteria

- Built-process HTTP proof: exact bearer/path/original correction bytes/key;
  compact UUID selectors; bounded closed inputs; malformed input sends nothing.
- Receipt proof: exact successor generation and dispatch identities; reject
  duplicate/unknown/null fields, bad UUIDs/digests, response substitution and
  credential-reflecting receipt metadata. Preserve unbounded positive generations,
  public default correction status and open escaped dispatch diagnostic statuses.
- Transport proof: canonical denials versus uncertain drops, redirects, malformed
  responses; one empty-body dispatch on HTTP/2 GOAWAY. A scratch binary removing
  the empty-body guard must fail that assertion; removing dispatch successor
  comparison must fail the otherwise-valid substituted receipt assertion.
- Real socket/Flow verification/PREP/PostgreSQL journey: retained canonical source
  fixture; CLI correction agrees with stored receipt and one saved successor;
  exact manual replay creates no second correction; explicit dispatch binds to
  that successor, with current authority required on retries. Outsider,
  foreign-project manager, revoked grant, suspension and invalid token deny.
  Real Celery publication to the configured in-memory test broker proves the
  dispatch boundary only, not distributed delivery, live inference or completion.
- Build/vet/module verify/tidy-diff, Ruff/format, links/stale wording/Commitrail;
  isolated PostgreSQL role/database cleanup; retain full hosted Backend/CLI checks.

## Discovered prerequisite

The production correction-dispatch dependency rolls back its identity-refresh
transaction before constructing PREP from the resolved ORM rows. SQLAlchemy
expires those rows on rollback; synchronous context access then raises
`MissingGreenlet` and the socket API returns 500 before scoped authority can
allow or conceal the request. The real public journey exposed this; an isolated
PostgreSQL diagnostic reproduces valid context before rollback and the exception
afterward. This is not repaired by changing CLI parsing or replacing the actual
API with a permissive fixture. Repairing that backend composition lies outside
this change's currently allowed CLI-only scope.
