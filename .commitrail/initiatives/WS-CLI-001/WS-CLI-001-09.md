# WS-CLI-001-09 — Declare a guide and its required setup inputs

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Create guide metadata, illustrative task examples and
  declared document targets through the existing public API.

## Intent

CLI08 creates a project shell. Its next setup boundary is the public
`POST /api/v1/projects/{project_id}/guides`, owned by
`GuideMutationService.create_guide`. Add `workstream project guide create
PROJECT_ID --input FILE --idempotency-key UUID`. The UTF-8 JSON file contains
the exact public ProjectGuideCreate body: version, optional change_summary,
required task_examples and required documents. Preserve field omission, null
where supported, text and order; reject malformed/duplicate/unknown fields.
The backend retains semantic validation, authority, immutable source membership,
setup identity, transaction and replay. No source text is extracted by the CLI.

This step intentionally ends at declared upload selectors and awaiting_documents,
not an approved or usable guide. Binary document upload needs a separate bounded
file-stream/transport proof, rather than hiding that risk in JSON creation.
Prefer one fixed typed command over generic HTTP passthrough, shell argument
arrays of large example text, or a second setup engine. No new human decision
or backend authority mechanism is required.

## Bounded change

Allowed: new `cli/internal/api/guide_create.go` and
`cli/internal/command/guide_create.go`; existing client.go and command.go;
new `cli/tests/integration/test_guide_create_http.py` and guide_create_journey.py;
test_public_self_service.py and the existing HTTP fixture's raw-body capture,
CLI/root README, affected roadmap claims, this
record, initiative overview and index. No backend, MCP, dependencies/workflows,
hidden routes, upload, guide edits/approval/activation, setup polling, grants,
local authorization/policy decisions, generated keys, retries or TUI.

Reuse the shared one-shot keyed POST and canonical error contract, adding
explicit response bounds to that private transport: existing commands keep
64KiB; guide creation alone permits 2MiB because 100 examples and document
declarations can exceed 64KiB. Bound the input file to 1MiB, require a regular
file, and never include its path/content or an OS error in diagnostics. Other
mutations keep their 8KiB bound. Require exact 201, unchanged bearer/key,
safe UUID selectors, no preflight, redirects, ambient proxy or transport replay.

Validate the complete closed ProjectGuideCreateResponse and nested examples,
documents and setup, including UUIDs/timestamps/hashes, non-null required fields,
nullable fields, unique document UUID identity and ordered declaration indices.
Bind project identity, version, change_summary, declared media types and example
values/order to the request. Bind document labels to the backend's existing
whitespace normalization (`" ".join(label.split())`), preserving original request
bytes; test Unicode whitespace and normalization collisions. Omitted and null
change_summary both return null; text remains exact. Optional example title
defaults to null, labels to an empty array. Null change_summary and example title
are valid; required fields, arrays and array members cannot be null. Creation
returns guide status `draft` and setup status `awaiting_documents` even on replay
of the stored creation receipt. contribution_policy_id,
contribution_policy_version_id, activation_operation_id, approved_by,
effective_at and superseded_at must all be null for this fixed receipt; validate
each syntactically valid non-null substitution and partial/full policy binding
as an unknown invalid response. Hash validation uses the existing syntax helper,
not a new implementation of backend canonical hashing.
Do not infer approval or active authority from a stored replay. Preserve raw
JSON in JSON mode; safely render all response fields in text mode. Invalid or
unexpected responses remain unknown mutation outcomes. Recovery guidance keeps
the same project, file contents and key, never claims rollback or invents an ID.

## Acceptance criteria

- Built-process HTTP tests prove exact body/field omissions and selectors,
  nullable values and Unicode, complete safe text/raw JSON, and input/response
  bounds (including a legitimate response over 64KiB).
- Reject malformed/duplicate/unknown fields and null required fields/members,
  substituted project, version/summary/examples/documents/lifecycle constants,
  invalid UUIDs/hashes/times, normalized duplicate
  document identities, and unexpected success status. Invalid local input sends
  no request and emits no file content/path or credential.
- Canonical 4xx is a known denial; malformed envelopes (including null details),
  drop, redirect, oversized response and HTTP/2 GOAWAY are unknown outcomes;
  one invocation transmits at most one POST body.
- Extend the one-bootstrap real FastAPI/PostgreSQL CLI journey. Assert OpenAPI
  registration, declared targets and awaiting_documents, direct exact replay,
  unchanged-body manual replay, mismatch denial and fresh creation denial for
  absent/foreign-project/revoked manager authority and suspended actor. Prove a
  fresh positive on the scoped grant's own project before a foreign-project
  denial and a fresh positive before revocation. Revocation leaves the actor
  active: regrant, prove a fresh positive, suspend, prove denial, reactivate,
  then revoke the restored grant. Restore the spare actor's active/ungranted
  baseline through public operations. No fake authority or private product writes.
- Existing process/API suite, Go verify/tidy-diff/vet/build, Ruff/format,
  workflow guards, links/stale/Commitrail and full hosted Backend remain required.
  No unit-test suite, coverage quota, skipped proof or weakened CI.

## Risk and review routing

Risk L1: larger untrusted response, file input, bearer handling, false setup
success or duplicate mutation after lost replies. Plan feasibility review before
code; architecture/docs, security and QA/test-delta focused assignments after
shared checks and a clean target. Human focus: declaration is not upload or
approval, exact file/body replay custody, full response identity and safe output.
