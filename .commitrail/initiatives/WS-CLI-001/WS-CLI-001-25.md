## Design and sequence

1. `task prepare TASK_ID --assignment UUID --file ZIP --idempotency-key UUID`
   streams the exact file once to the public preparation POST. Optional summary,
   attestation and predecessor are explicit; omitted/empty semantics match the
   server. Hash/stat before and after transfer; reject changed source on success.
   Display the exact bounded preparation receipt or sanitized blocking PRE
   findings. Non-ready preparation is not a created Submission.
2. `task submit TASK_ID --assignment UUID --admission UUID` sends the matching
   optional packet to the public Submission POST. Admission/packet identity is
   the server's replay key; do not invent another creation idempotency key.
   Lost/malformed replies remain uncertain, with action-specific recovery text.
   Manual exact replays work across CLI restarts without local state.
3. `task submissions TASK_ID`, `submission show SUBMISSION_ID`,
   `submission findings SUBMISSION_ID [--run UUID]` use only their public GETs.
   List reads fetch one bounded page and expose the opaque continuation token.
   Submission status is not inferred acceptance; checker status/results are
   distinct from human review. Never follow finding paths or fetch artifact URLs.
4. Reconcile docs and prove the built CLI against adversarial HTTP and real
   API/PostgreSQL/artifact custody. Public native proof must exercise preparation,
   creation and reads, not call those commands through hidden test ports.

The current API has no metadata-only preparation GET. Recover readiness by an
explicit repeat of the same preparation command/bytes/key; never advertise this
as a read-only poll. #495's revision-change summary is not exposed yet; state
that limitation rather than inventing a response field or historical fact.

## Acceptance criteria

- Fixed public paths, exact selector/packet bytes and caller key, bounded regular
  file streaming, no HTTP redirect/proxy/replay, and no credential disclosure.
- A non-ready preparation cannot invoke creation or claim submission success.
  Blocking PRE feedback is distinct from infrastructure/uncertain failure.
- Exact admission replay preserves the canonical result; changed packet denies;
  dropped replies remain uncertain and never cause a second request.
- Closed receipt/history validation rejects malformed, foreign and duplicated
  identities; preserves full integer range and nullable fields. Text is escaped;
  JSON is complete. History is bounded with explicit continuation.
- Real contributor reads deny foreign actors/projects, revoked/suspended callers;
  exact stored ZIP hash/size, immutable Submission and dispatched evaluation
  identity match the successful CLI journey. No direct SQL creates the Submission.
- Existing CLI commands, full test selection and backend authority are unchanged.

## Risk and review routing
