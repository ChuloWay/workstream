# WS-CLI-001-28 — Inspect actor identities and administrative authority

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: six existing privileged public GET operations become
  explicit CLI reads, without moving admission or authorization into the CLI.

## Intent

Issue [#606](https://github.com/Flow-Research/workstream/issues/606) closes the
public API-to-CLI gap for exact actor profile and identity-link inspection,
scope-filtered administrative grant history, and the permission/role catalogues.
`whoami` and `profile update` remain separate self-service operations. Backend
AUTH and ACTORS own fresh authority, denial concealment, exact identity and
privacy-bounded projections; a successful read is not later-write authority.

## Bounded change

Allowed: this record; new cohesive `cli/internal/api/admin_inspection.go` and
`cli/internal/command/admin_inspection.go`; one registration in
`cli/internal/command/command.go`; focused built-binary process and real
API/PostgreSQL tests under `cli/tests/integration/`; affected `cli/README.md`,
top-level README and `docs/roadmap_status.md` claims. The CLI lead owns initiative
overview/index reconciliation. Coordinate the namespace and shared registration
before code. Reuse existing client transport, strict JSON/UUID/cursor validators,
safe output and test fixtures; no `client.go` edit is expected.

Prohibited: backend/API/schema or policy changes, new authorization decisions,
Flow token handling, actor enumeration, generic raw-HTTP command, grant mutations,
new dependencies/CI gates, compatibility variants, automatic pagination or
write retries, and unrelated CLI journeys. Do not duplicate self-profile reads.

Plan: (1) confirm command grammar with CLI lead; (2) implement typed read
methods and closed response validation against the six public schemas, including
selected actor/scope/filter bindings and bounded bodies; (3) add a single
`admin` namespace with explicit actor, grant and catalogue commands and safe
text/JSON output; (4) prove exact requests, valid responses, malformed/mismatched
responses and denials in a built binary; (5) run a signed real API/PostgreSQL
journey that distinguishes covering authority from ungranted, revoked and
suspended access; (6) reconcile current documentation, deterministic checks and
review before PR handoff.

## Acceptance criteria

1. `admin actor show ACTOR_ID`, `admin actor identity-links ACTOR_ID`,
   `admin actor role-grants ACTOR_ID`, `admin role-grants`, `admin permissions`
   and `admin role-definitions` map one-to-one to the six exact public GET
   routes. The identity-links route returns one current link, not a list. Both grant
   lists require `--scope system|project`; project scope requires `--project-id
   UUID`, system scope forbids it. `--status active|revoked|all`, `--limit 1..100`
   and opaque `--cursor` preserve backend semantics without auto-pagination.
2. Reject malformed selectors/filters locally before dispatch; preserve valid
   caller UUID spelling in requests and compare response UUID identity, not
   spelling. Validate required/nullable fields, role/scope/status/version,
   selector bindings, counts, unique IDs,
   and pagination limits. Never treat a malformed success or reflected bearer
   as a trustworthy result.
3. Use the existing origin/bearer protections, response-size and timeout bounds,
   sanitized failure mapping and terminal-safe output. No local role cache or
   permission evaluation. JSON is machine-readable; text labels grant history
   and catalogues as observations, not authority.
4. Built-binary process tests cover all six exact wires, filters/cursor, valid
   actor kinds and grant states, empty pages, malformed/mismatched success,
   denial concealment, token reflection, and no dispatch on bad input. A real
   signed API/PostgreSQL test confirms actual role/scope authority and fresh
   denial after revocation/suspension using isolated data and existing helpers.
5. Existing commands, tests and contracts remain unchanged. CLI README and
   roadmap describe intended merged exposure without claiming deployment or
   new server capability. No local spreadsheet export is modified unless
   roadmap changes require it and exports are present.

## Risk and review routing

Risk: `L1`, sensitive actor/identity/grant disclosure through an untrusted
client boundary. Plan review before code. Required internal tracks after shared
deterministic proof: security, QA, test delta; add architecture, reuse/dedup and
documentation for the new command boundary and current claims. The lead owns
reviewer allocation and frozen-head handoff.

Human review focus: privilege separation from self-profile, exact actor and
project binding, grant scope/status/cursor truth, privacy and bearer redaction,
and credible fresh-denial proof. The CLI cannot certify future authority.

## Review findings

`STATUS001` found that a revoked row was accepted when `--status` was omitted,
although the backend defaults that query to active. The CLI now validates the
effective active default without adding a wire parameter; built-binary tests
prove a valid active row and reject a revoked row on both grant routes.
`REUSE001` found the closed five-role validator duplicated in the contributor
read. Both consumers now use one narrow validator in that existing owner file.
