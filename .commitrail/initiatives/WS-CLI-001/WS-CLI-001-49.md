# WS-CLI-001-49 — Contributor guide and findings in the terminal

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: Replace guide/findings handoffs with bounded interactive reads and explicit verified guide downloads.

## Intent

Issue #688 tracks the remaining terminal experience. Main's read-only workspace
opens exact task/context/intake and Submission details but sends users back to
explicit commands for detailed findings and guide originals. The public APIs
and their validation already exist. This slice removes those handoffs without
adding product mutations or changing backend authority.

## Bounded change

Extend existing TUI navigation, request generations, cancellation and safe text
rendering. WorkContext supplies assignment-sensitive ordered guide metadata;
DownloadGuideDocument verifies exact same-origin content, SHA-256 and byte count.
Use an explicit destination entry and confirmation before downloading. Extract
the existing CLI private-file/no-overwrite publication operation into a shared
owner if needed; both callers must use it, not duplicate filesystem policy.
Keep binary documents out of terminal rendering; no system viewer launch or
shell execution. Metadata must never be labelled verified bytes.

Expose typed paged findings through the existing validated SubmissionFindings
operation, updating affected explicit callers rather than adding a second
transport/decoder. Display exact run identity/current-versus-historical state,
checker/check ID, status, severity, path/line, message and suggested fix.
Continuation is explicit and bound to selected Submission/task; never infer
acceptance from checker success. Navigation/refresh invalidate stale responses;
denial clears affected observations. Every displayed untrusted value uses the
existing terminal sanitizer and bearer suppression.

Allowed paths: cli/internal/tui/, affected api/submission_reads.go and its
callers/tests, existing guide download command and a narrowly shared download
owner, cli/tests/integration/test_tui_http.py and focused guide/findings process
tests, cli/README.md, docs/design/cli-terminal-experience.md,
docs/roadmap_status.md and affected WS-CLI-001 records/index when their next
boundary changes. The shared owner may use platform-specific permission files
and tests; cli/go.mod may promote the already-pinned x/sys dependency from
indirect to direct for Windows file-handle ACL operations. No new dependency or
version, backend, workflow or release changes.

## Boundaries and alternatives

Do not add claim/start/prepare/submit, polling, credential storage, local replay
journals, PDF rendering, automatic viewer launch, task examples, directory
creation, overwrite, or download-all implicit chains. Existing explicit commands
remain available. A separate raw-HTTP TUI client or duplicate download helper
was rejected because it would fork validation and custody rules.

## Risk and review routing

L1: untrusted terminal data and local filesystem publication. Plan review before
implementation; focused security, QA and reuse/architecture review of affected
owners; documentation review for capability claims. Human merge remains required.
No new authority decision is needed; if a backing contract is missing, report
the gap rather than invent it.

## Acceptance criteria

- Assigned task guide screen preserves exact server ordering, identities and
  hashes; no documents for an unassigned task or task-example disclosure.
- Explicit download writes private temporary content; checksum/size failure or
  missing bytes publishes no final file. Existing files/symlinks are not replaced.
  Cancellation/navigation cannot silently publish an unobserved success.
- Findings load only for the selected Submission and task, preserve all returned
  statuses and historical/current run distinctions, and follow explicit cursors.
- Denial, malformed/misbinding responses, token/control-character content,
  late responses and quit remain safe. Narrow/plain terminals stay usable.
- Focused Go tests and real socket/PTY process tests exercise new screens and
  failure boundaries. Existing native suite runs unchanged on all four platforms;
  no skipped assertions or CI weakening. Retain existing public PostgreSQL
  guide/findings authorization proof; a TUI test does not certify hosted service.
- Update affected capability ledger/README/design claims together; run markdown
  links, stale wording, Go tests/vet and review before merge readiness.

## Human review focus

Confirm destination/confirmation usability, exact locked identity visibility,
no-overwrite and integrity failure behavior, and honest checker outcome labels.

## Concrete state and owner contract

Mine detail keeps Overview, Context and Intake in their existing order, then
adds Guide. Guide freshly reads WorkContext; arrows select one ordered document.
`d` edits an existing-directory destination, Enter opens confirmation showing
task/document identity, directory and computed UUID filename, and `y` starts
staging. Esc cancels editing/confirmation without I/O. No directory is created.
Submission detail Tab alternates Overview and Findings. Findings fetches 50
runs; `n` replaces that page using its exact cursor, `r` restarts at page one.
Back, refresh, project changes, denial and quit invalidate pending work.

The narrow shared owner is `cli/internal/download/`. Move the bound-root and
private-publication behavior from `command/guide_reads.go` there and update
all consumers: `command/task_guide.go`, `command/guide_reads.go` and
`command/task_batch_source.go`. CLI consumers stage then publish synchronously;
do not preserve duplicate implementations. TUI registers an abortable stage
before dispatch. Async work can only write/verify/sync/close temporary bytes.
Only the current-generation receive may synchronously publish the no-overwrite
hard link and set the visible success state, before another key is processed.
Abort/Publish are idempotent and race-serialized. Invalidation/Close marks an
in-flight stage aborted; cleanup does not require delivery of its response,
including on Windows where a writer may still hold an open file.

Windows mode bits do not enforce private access. Create the stage atomically
with a protected current-user-only DACL relative to the already-bound directory
handle, with exclusive-create/non-directory semantics; failure returns no stage.
Do not tighten inherited permissions after creation: a foreign reader could
retain a handle acquired before tightening. POSIX uses mode 0600.
Native tests inspect the actual platform permission boundary and exercise
symlink refusal without skipped assertions. This replaces the incorrect
cross-platform assumption that 0600 alone provides private staging.

SubmissionFindings returns a typed one-of result containing Raw plus Page or
Run (only the mode-appropriate member populated), using its existing decoder.
CLI JSON and text continue rendering Raw unchanged; TUI consumes Page. Receive
checks every run's task and Submission against selected row/detail, as well as
request cursor, generation and selector. Preserve nullable fields, predecessor
and current-run flag. No alternative decoder or transport is introduced.

Named proof additions: Go typed page/exact-run and unchanged raw-output tests;
TUI selection/confirmation/current-receipt tests; download stage tests for
bound/symlink directories, existing file/symlink, native private temporary content,
checksum/size/missing/transport failure, and delayed writer Abort cleanup.
Extend test_tui_http.py and its tui_terminal_support.py binary-response fixture
to exercise actual PTY navigation, explicit confirmation, download success,
cancel/quit before delayed completion, findings pagination/misbinding, every
finding status and hostile text. These tests remain in the native four-platform
suite. Retain prior input, denial and terminal lifecycle assertions.
