# WS-CLI-001-34 — Read exact task audit context and evidence

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Public CLI reads for the two existing Audit Authority task routes in issue #610.

## Intent

The API already exposes exact historical locked-context references and a bounded
task lifecycle evidence page to covered Audit Authorities, but the CLI cannot
reach either. Add explicit audit commands for a known project/task pair without
reinterpreting those facts as contributor or Project Manager projections.
Reading a page does not confer authority for the next page or any write.

## Bounded change

Allowed: new `cli/internal/api/task_audit.go` and
`cli/internal/command/task_audit.go`, minimal registration in
`cli/internal/command/command.go`, built-process and native public-API tests in
`cli/tests/integration/test_task_audit_*.py`, `cli/README.md`, affected
`docs/roadmap_status.md` and `README.md` claims, this record, and the CLI
initiative overview/index when their durable boundary changes.

Prohibited: backend routes, schemas, SQL, authorization or storage changes;
shared transport/auth changes in `cli/internal/api/client.go`; new dependencies,
CI changes, hidden API calls, full audit export, audit mutation, role caching,
automatic retries, compatibility aliases, or other CLI issue commands.

### Bounded year-zero repair on this PR

Problem and rationale: Python's `datetime.fromisoformat` and the backend's
`TaskEvidenceCursor`/`AuditTaskEvidence` contract permit years 1..9999, but Go's
RFC3339 parser accepts `0000`. The CLI therefore accepts an impossible audit
event timestamp or continuation and may dispatch a caller-supplied cursor the
backend must reject. This is a response-boundary and input-boundary validation
gap, not a request to widen or change backend history.

Allowed repair files: this record, `cli/internal/api/task_audit.go`, and
`cli/tests/integration/test_task_audit_http.py`. Add one audit-local predicate
requiring an aware RFC3339 timestamp whose parsed year is 1..9999, and use it
for audit event timestamps, returned next cursors and supplied cursors only.
Keep the original timestamp text on the wire; retain exact page ordering and
cursor-last-event comparison. The shared `validTime` in `client.go` has many
non-audit consumers and is deliberately outside this repair. No global time
refactor, backend/schema/route change, new dependency, CI change, or other CLI
command is authorized. Existing locked-context and non-audit behavior remain
unchanged.

Acceptance and proof: built-binary process tests accept years `0001` and
`9999` for audit evidence and cursor, reject year `0000` in an event and
returned cursor as `invalid_api_response`, and reject year `0000` in a supplied
cursor as `invalid_arguments` before any HTTP dispatch. First run the new
regression against a binary built from pre-repair head `82b93b0d` and show
that it fails; then rebuild and run the same test plus affected existing audit
and shared-boundary tests, `go vet`, module verification, Ruff and record checks.
No native database or storage behavior is claimed by this pure parser repair.

Risk remains L1 because this is a sensitive Audit Authority read surface, but
the repair is confined to local input/response validation. Security and
QA/test-delta review should verify backend parity, non-disclosure and retained
cursor semantics; architecture/reuse review should verify the global helper and
its consumers are not widened. Human focus: `0000` denial without excluding
Python-valid boundary years, and no change to authorization or later-page
freshness. No new product choice is required; human PR merge authority remains
separate.

## Acceptance criteria

1. `audit task locked-context PROJECT_ID TASK_ID` calls only the public audit
   locked-context GET. Validate the complete closed audit lineage, exact route
   UUID identities, positive generations and digest forms. Do not include the
   management-only post-submit summary or private policy bodies.
2. `audit task evidence PROJECT_ID TASK_ID [--limit 1..100] [--cursor JSON]`
   calls one bounded public audit evidence page. Preserve the exact fixed event
   projection and JSON `next_cursor`; validate nullable references, aware time,
   exact project/task scope, page bound/order and continuation anchored to the
   last event. Accept only the backend's four-field, at-most-512-character
   structured cursor, passed unchanged as a URL query value. Each request uses
   the caller bearer and backend's fresh current authority; the CLI never
   follows automatically.
3. JSON output remains machine-readable and terminal-safe; text escapes
   controls. Reject malformed, extra, missing, null-required, wrong-scope,
   oversized or bearer-reflecting success bodies without partial output.
   Denied/foreign requests remain backend-owned concealed failures.
