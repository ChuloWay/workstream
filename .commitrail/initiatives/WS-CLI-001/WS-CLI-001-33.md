# WS-CLI-001-33 — Discover exact-project contributor candidates

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: A covered Project Manager can inspect one privacy-safe contributor-candidate page through the public Workstream CLI before making a separate, explicit role-grant decision.

## Intent

Project Managers need the backend's existing candidate projection when selecting a target for an explicit Submitter or Reviewer grant. The CLI currently provides issue/revoke and grant-history commands but not candidate discovery. Discovery must remain an observation: it does not qualify an actor, imply permission for a later write, or issue a grant.

## Current behavior

`backend/app/modules/authorization/router.py` exposes `GET /api/v1/projects/{project_id}/contributor-candidates`. `schemas.py` returns only `actor_profile_id`, nullable `display_name`, and a count-free `next_cursor`. The read service checks current exact-project management authority before backend-owned cursor decoding and actor selection. Its only query inputs are `limit` (1–100, default 50) and an opaque cursor (at most 512 characters). `cli/internal/command/project_role_mutations.go` already groups the explicit grant decisions and retained grant reads; no CLI operation reaches this candidate route.

## Design and decisions

Add `project role-grant candidates PROJECT_ID [--limit N] [--cursor TOKEN]` beside existing issue/revoke/list/show. Reuse the public API client, UUID identity and page-query validation, strict JSON decoding, bearer-safety check and terminal-safe text output. Send exactly one GET per invocation; preserve the opaque cursor and authorized JSON without a grant lookup. Validate the two-field row, nullable display name, page cardinality and normalized duplicate actor IDs. The backend alone owns project/caller cursor binding, actor/link lifecycle membership, current authority and grant eligibility. A separate actor-list endpoint, local scoring/filtering and implicit grant were rejected because no such public candidate contract exists.

## Acceptance criteria

- The command makes one exact public GET with its selected project, limit and optional cursor. JSON preserves the complete authorized response; text escapes controls and labels the result as candidates, not authority or qualification.
- Invalid project, limit or cursor fails before HTTP. Missing/extra/null-invalid fields, duplicate normalized actor IDs, malformed or credential-reflecting success fails with empty stdout. Null display names remain valid.
- Denial, foreign-project concealment and malformed/query-mismatched cursors retain backend-owned errors. The CLI does not sign, interpret or automatically follow cursors.
- Built-binary process tests prove request/response and negative paths. One existing isolated real API/PostgreSQL journey compares CLI and direct public API pages, backend cursor binding, live authority denial and no role-grant side effect. Existing role-grant commands remain unchanged.
