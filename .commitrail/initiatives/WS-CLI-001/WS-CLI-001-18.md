# WS-CLI-001-18 — Explicit complete-guide activation

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Managers activate an exactly inspected and separately approved guide through the existing public API.

## Intent

The CLI can inspect the complete proposal, approve intake and evaluation policy,
and save/dispatch corrections. It cannot yet perform the manager's final guide
activation. Add `project guide activate PROJECT_ID GUIDE_ID --input FILE
--idempotency-key UUID`, sending the original closed `GuideActivationInput`
bytes once to public `POST /api/v1/projects/{project_id}/guides/{guide_id}/activate`.
The manager explicitly prepares selections from the existing `post-policy` read.
Do not fetch latest, approve missing policies, discover Finance contents, decide
readiness or evaluate rules locally. A nullable activation-context selection is
not permission to invent its value. The backend owns fresh manager authority,
readiness, locked lineage, supersession and the single activation transaction.

Validate the complete immutable `GuideActivationReceipt`: exact echoed command
and caller key, UUID identity rather than selector spelling, contribution
project/policy/version binding, UUIDv7 operation, positive arbitrary-range
integers, activation generation equal to selected mutation generation plus one,
timezone-bearing effective time and public prior-project status. Reuse existing
post-target/selection validation, transport, file reader and escaped text/JSON
renderer. Keep digest computation, adapter validation and authorization on the
backend. Unknown outcomes leave stdout empty; recovery is deliberate replay
using the unchanged selectors, input bytes and key. No automatic retries.

## Bounded change

Allowed: new `cli/internal/{api,command}/guide_activation.go`, registration in
`guide_create.go`, reuse-oriented selection validation in `guide_post_policy.go`,
new `cli/tests/integration/test_guide_activation_{http,public_api}.py`, CLI README,
README, affected roadmap claims, this record, initiative overview and index.
Prohibited: backend changes, hidden routes, policy/schema/migration changes,
dependency/workflow changes, Finance commands, task import/submission, automatic
reads/approvals/retries, compatibility paths, unit-test suites and test weakening.
If an actual backend prerequisite fails, reproduce and diagnose it before
proposing the smallest repair; do not weaken the public journey to manufacture a pass.

Rejected: automatically turning the latest display package into activation,
combining decisions or copying backend readiness rules. Those would hide the
manager's exact selections and create a second lifecycle authority.

## Acceptance criteria

- Built process: exact public bearer/path/key/original JSON, canonical and compact
  UUID spellings, full first/successor activation inputs and unbounded generations.
  Invalid/duplicate/unknown/null input, paths or keys send no request.
- Receipt: reject missing/null/unknown members, substituted command/key or
  contribution ownership, invalid operation/timestamp/status, generation mismatch,
  malformed adapter IDs and credential reflection. Escape all terminal text.
- Transport: distinguish canonical denial from uncertain redirects/drops/server
  or malformed responses; one POST under HTTP/2 GOAWAY; deliberate replay only.
- Actual socket/Flow/PREP/PostgreSQL: reuse canonical retained-source fixtures,
  real public intake approval and canonical post-policy worker, separate public
  Finance publication and manager post-policy approval. The built CLI activates
  from the displayed selections; SQL proves one receipt/audit and active guide
  with exact locked policies. Exact replay is unchanged; changed-input/key reuse,
  wrong stored project/outsider/foreign manager, invalid token, suspension and
  revoked authority deny without another activation. This is a local HMAC verifier
  and retained compilation fixture, not live inference or deployment certification.
- Countercheck: removing exact command binding must cause the otherwise-valid
  substituted receipt test to fail. Retained backend rollback/concurrency tests
  remain intact; this change does not claim to re-prove all unchanged backend rules.
- Shared checks: build/vet/module verify/tidy-diff, Ruff/format, links, stale scan,
  Commitrail/diff checks, isolated database/role cleanup; full hosted CI remains.

## Risk and review routing

L1 authenticated lifecycle write, client only. Plan review before code; three
focused assignments cover architecture/docs/reuse, security and QA/test delta.
Human focus: deliberate exact selections, complete receipt binding, backend-only
authority and manual recovery. No additional human design decision is needed.
