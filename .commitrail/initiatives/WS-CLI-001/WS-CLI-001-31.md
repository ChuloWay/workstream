# WS-CLI-001-31 — Download retained task-import source through public custody

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: A covered caller can save an exact verified task-import JSON source using only the public Workstream API and the existing CLI, without overwrite or partial publication.

## Intent

[Issue #605](https://github.com/Flow-Research/workstream/issues/605) closes the CLI gap for the existing `GET /api/v1/projects/{project_id}/task-import-sources/{source_id}/content` read. The backend remains the authority for current actor, project, source and provider custody. A prior status read supplies an immutable SHA-256 and byte count for an independent client-side check, not permission for the later content read or any write.

Review finding `SECQA-605-001` identified a local directory pathname-swap race shared with the existing guide-original downloader: each checked a real directory before a remote metadata read but opened that pathname only afterward. This change binds both commands to the checked directory identity before the remote read, so a later rename/symlink replacement cannot redirect verified bytes to a different directory.

The command is `workstream project task-batch source-download PROJECT_ID SOURCE_ID --download DIR`. `DIR` must be an existing real directory. It reads exact source status, requires the source to be verified, then requests content through the same-origin public endpoint. The returned stream must match application/json, the immutable size and SHA-256, with a bounded read. It is written to a private temporary file and published as `SOURCE_ID.json` only after verification; an existing name is never overwritten. Text output names the saved file; JSON output is a bounded machine-readable receipt without provider coordinates or raw source bytes. The status and content reads each retain backend authorization; the CLI does not infer authority from a successful first read.

## Acceptance criteria

- Exact authenticated status/content public GETs; no request for invalid selectors or unsafe directory, and no provider URL or credentials.
- Crossed/malformed metadata, non-verified source, denied/missing content, wrong MIME, wrong count or digest, overlong stream, broken stream, symlink or existing output name never publish a partial or overwrite another file.
- An unchanged verified source saves exact bytes and reports one safe filename in text and JSON; existing source declare/upload/status/import commands retain their behavior.
- Built-binary process tests exercise request shape and negative paths; a real socket/PostgreSQL/verified MinIO source journey proves actual backend custody and fresh denial after manager grant revocation.
- A synchronized directory rename/symlink replacement during source-status or guide metadata GET cannot redirect downloaded bytes to the replacement directory. Both commands publish only under the previously checked and opened directory identity, with static symlink and no-overwrite behavior retained.
