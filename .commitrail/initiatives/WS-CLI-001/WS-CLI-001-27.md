# WS-CLI-001-27 — Inspect manager task context and retained evidence

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Seven existing Project Manager GET contracts are reachable through the Go CLI with exact project/resource selectors, bounded response validation, safe text and complete JSON, without changing backend authority.

## Intent

Issue #602 closes the manager API-to-CLI gap for task requirements, locked context, work context, task submission history, exact submission detail, checker-run history and exact run detail. Contributor commands already read their distinct projections. The backend has separate project-scoped routes and DTOs; the CLI must not call contributor routes, substitute a latest record for a supplied historical ID, or treat a read as authorization for a later action.

The lead owns initiative overview/index coordination. Reuse existing transport, UUID identity, pagination and terminal-safe output.

Prohibited: backend, AUTH, migrations, CI/workflows, dependencies, new endpoints, contributor projection aliases, automatic pagination or retries, implicit latest selection, policy/lifecycle decisions, private imports or SQL in shipped CLI, artifact fetches, release packaging and unrelated commands.

## Acceptance criteria

- All seven manager operations make exactly one fixed public GET each and expose documented inputs and machine-readable output; existing contributor and manager commands remain unchanged.
- Response validation rejects missing/unknown/duplicate or foreign identity fields, malformed lineage/results, and unsafe or oversized replies; preserves full integer range, nullable fields, and opaque server-bound cursor bytes.
- Built-process tests cover negative requests/responses and no-request local failure. A real API/PostgreSQL journey checks exact historical selectors, project isolation, denied/revoked authority and backend-owned responses; fixture setup is identified separately from tested CLI reads.
