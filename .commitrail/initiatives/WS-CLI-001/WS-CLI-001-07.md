# WS-CLI-001-07 — Inspect governing contributor work requirements

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: Read the exact task work context and submission
  requirements through two existing public contributor REST operations.

## Intent and inspected owners

CLI discovery and claim/start are delivered. Contributors still need the guide,
locked policy selectors, server-owned action hints and intake requirements before
working. `tasks/router.py` publicly exposes `GET /tasks/{task_id}/work-context`
and `GET /tasks/{task_id}/submission-requirements`. `AuthorizedTaskCommands`
owns fresh authorization, assignment visibility and exact historical policy
resolution. The latter is not a latest-guide lookup. Submission intake remains
hidden: this change must not create an upload command or imply completed intake.

## Bounded change and design

Allowed: cohesive `cli/internal/api/task_context.go` and
`cli/internal/command/task_context.go`; command registration in
`contributor_tasks.go`; process integration proof in
`test_task_context_http.py`; additions to the existing contributor API journey;
CLI/root README, affected roadmap claims, this record, overview and index.
Existing response/UUID/transport/output helpers may be extended only where
required, without weakening existing commands. No backend, MCP, workflows,
dependencies, manager/operator/audit routes, files/downloads, local policy
evaluation, cached authority, JWT decoding, preflight or automatic actions.

Add `workstream task context TASK_ID` and `task requirements TASK_ID`. Each sends
one fixed GET with the unchanged caller bearer. Reuse selector identity and
path escaping, bounded responses and safe error transport. Do not combine both
reads into a pretend atomic snapshot or use a context response as authorization.
Workstream owns hints; `claim`/`start` still independently authorize execution.

Decode exact public response shapes with duplicate/unknown-field rejection,
non-null required scalar/array/object checks and complete nested member shapes.
Work context validates selected task identity, task/project/guide composite
project identity, UUID policy identities, positive integer policy generations,
canonical SHA256 policy hashes, guide/time shapes, exact contributor task
projection and closed server hint shapes. Do not recompute hints from state or
interpret policy contents. Requirements validate selected task and project
identities, nonblank guide version, string arrays, booleans, optional nullable
strings/integers and exact artifact/evidence/forbidden/storage/packaging shapes.
Nullable fields omitted by FastAPI remain valid; null required booleans or
array members are not silently converted to zero values. Validate contract
shape, not backend business eligibility or checker acceptance.

JSON preserves successful API bytes. Human output prints every returned public
field with safe terminal escaping, including nested rules; storage references
and guide metadata are display-only, never fetched or executed. Reject foreign,
malformed or management-only replies before producing any successful output.

## Acceptance and feasible proof

- `test_task_context_http.py` invokes the built binary against the existing HTTP
  fixture. Prove both exact paths, one GET/no preflight, unchanged bearer, compact
  and supported UUID spelling parity, complete safe text/raw JSON and valid
  optional omissions/nulls. Group malformed cases by distinct failure boundary:
  substituted composite identities; null/scalar nested objects or members;
  missing/duplicate/unknown fields; invalid policy UUID/generation/hash; unsafe
  text; malformed hint and packaging shapes; oversize/denial/redirect; invalid
  local selectors with no request. Reuse existing transport proof, not duplicate
  its whole matrix for each read.
- Extend `exercise_contributor_task_reads` in the existing real
  FastAPI/PostgreSQL journey. Assert both routes are OpenAPI-visible and compare
  complete CLI output with authorized public API output. Use existing stored
  approved-guide projects/tasks and canonical grants, not route overrides.
  Read ready, own claimed and in-progress work; assert server hints progress
  through claim/start/none and requirement values stay tied to the locked guide.
  Absent, Reviewer-only, foreign-project, peer-owned, revoked and suspended
  controls must deny each read under its actual API status semantics. A positive
  control proves each caller/resource exists before the changed denial boundary.
  No private lifecycle processing or fabricated submission is required.
- Preserve all existing tests. Prove a composite-identity rejection case fails
  when its guard is removed in an out-of-tree test-of-the-test variant. No
  coverage quota, test count target, timeout increase or selection weakening.
