# WS-CLI-001-03 — Inspect an authorized project

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Complete the CLI's exact-project inspection journey
  with the public role-bounded project response alongside `project access`.

## Intent

Let humans and agents inspect a known project without leaving the terminal.
The user authorized continued CLI implementation after PR #472 merged.
Do not invent project discovery: no public project-list contract exists here.

## Current behavior

The CLI reads caller authority, but cannot display the corresponding project.
`backend/app/modules/projects/router.py:get_project` publishes
`GET /api/v1/projects/{project_id}`. `ProjectService.project_identity_response`
returns either `ProjectResponse` (administrative authority) or the three-field
`ContributorProjectResponse` (exact contributor grant). The backend owns the
projection, project-state guards and concealed denials. Existing API tests
arrange a project and administrator grants through public routes.

## Bounded change

### Allowed

- A cohesive project-read owner under `cli/internal/api/`, reusing the existing
  transport, UUID identity, strict JSON and timestamp validation.
- `cli/internal/command/command.go`: `project show PROJECT_ID` and safe output.
- Built-process integration tests under `cli/tests/integration/`.
- CLI/root README, affected roadmap claims, this record, overview and index.

### Not allowed

- No backend, MCP, workflow, dependency, authorization or policy changes.
- No hidden routes, list/search endpoint, generic API command, extra preflight,
  automatic retry, local role selection, credential storage, prompt or TUI.
- No unit-test layer, coverage gate, skipped or weakened existing proof.

## Design and decisions

Make one fixed GET with one escaped path segment, forwarding the bearer
unchanged. Accept only a UUID selector (the backend resolves project selectors
as UUIDs), including supported compact spellings; preserve its spelling on the
wire and compare the returned UUID identity. Bound selectors to 100 bytes and
reject invalid selectors before
the network; never concatenate raw input into a path or query.

Validate exactly one of the two public shapes, not a permissive partial union:
`id`, `name`, `status`, or those fields plus `slug`, nullable `description`,
`created_at`, `updated_at`. Required strings cannot be null; identifiers and
timestamps must be valid. The CLI does not choose a shape from cached roles,
invent missing metadata or convert a minimal response into a full one.
Preserve successful JSON and escape terminal text. Both shapes share the same
visible identity fields; administrative metadata appears only when returned.

An isolated new client or imported MCP library would duplicate the current
transport. A generic OpenAPI dispatcher would expose unintended operations.
Neither is needed. The named command pairs with existing `project access`;
project setup/write journeys and distribution remain later work.

## Acceptance criteria

- [x] One public GET, original UUID selector safely encoded, unchanged bearer;
  no local authorization or preflight request.
- [x] Full and minimal responses render correctly in text and exact JSON;
  malformed, partial, null, duplicate, unknown-field and mismatched-ID responses
  cannot report success.
- [x] Unsafe/invalid selectors and unsupported flags cause zero requests;
  redirects, failures and bounded metadata reuse existing transport protection.
- [x] Real API/PostgreSQL proves manager full projection, contributor minimal
  projection, unsupported/foreign authority denial, revocation and suspension.
  Both projects and the contributor grant must exist in the fixture; no direct
  database mutation is used to bypass project lifecycle setup.
- [x] README, roadmap and initiative navigation describe the added inspection
  boundary without claiming list discovery, distribution or lifecycle delivery.
