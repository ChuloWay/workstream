## Design and decisions

### Bounded CLI proof partition

The new terminal and proof-runner tests add 63 cases to the existing broad
socket group, which reached its 300-second limit in hosted verification.
Collection inspection establishes 339 cases partitioned into 276 existing
cases and the exact two-file 63-case TUI group, with no overlap or omission.
Keep both groups in the required HTTP partition, each using the canonical
isolated runner and a distinct cleanup metadata file. This does not depend on
another workflow's result or remove native per-platform proof. The CI-integrity
review requires exact argv assertions and simulated success/failure/timeout
propagation for all six groups. Hosted execution must still prove the unchanged
overall job budget; collection equality alone is not runtime evidence.

The first partition still exhausted the broad group's budget at the same
252-node boundary as the original run, immediately before the task-guide
context-deadline case. All three intentional deadline probes passed separately
in 40.99 seconds, discriminating cumulative cost from a hung test. Move all 25
unchanged task-guide cases to the existing guide HTTP group: broad 276 → 251,
guide 175 → 200, with exactly those 25 identities moved and no lost or duplicate
cases. Keep six groups, their original timeout limits and isolation semantics.

A full hosted run passed in 12m42s, but its unchanged-source ready-state run
exhausted the 15-minute job limit during the final batch group after all earlier
groups passed. The cumulative single-job budget is therefore not robust to
observed runner variation. Use one fixed two-value matrix: `http` runs broad
HTTP, terminal/proof and guide HTTP; `api` runs public API, self-service and
batch journeys. Each partition independently builds the exact checkout and
uses the existing PostgreSQL/MinIO setup and cleanup. Do not introduce binary
handoff artifacts, new fixtures, retries, or larger per-test/per-job limits.
Disable matrix fail-fast so one failure does not cancel the other partition's
evidence. Existing backend full-suite and final checks require the reusable
workflow's aggregate success. CI review must protect the closed partition,
exactly one assignment of every existing group, and failure propagation;
removing either partition or a required condition must fail a focused gate.

### One contributor workspace

`workstream tui [--plain]` is explicitly opt-in. Require interactive stdin
and stdout before any API call or terminal mode change; never reopen `/dev/tty`
to bypass redirection. Reject `--output json` with the existing structured
argument-error convention (exit 2), not an alternate JSON dashboard. Missing
environment/invalid origin use existing client validation. Existing commands
never enter the TUI; the only expected old help difference is the new root
`tui` entry. No new global flags or output changes.

After actor binding, fetch one project page. Selection opens Ready; Tab cycles
Ready/Mine/Submissions, fetching only the selected view. Fixed limit 50, Mine
uses `ProjectID` plus `State=active`, Submissions uses `ProjectID` only.
`n` replaces the page using its untouched continuation; no concatenated feed,
automatic next-page request, cursor interpretation or backward-page cache.
`r` resets to page one and clears selection/detail; project/tab change resets
that scope. `/` filters fetched titles/names only and is labelled local; it
does not alter server filters or cursor scope. Page length is not a total.

Enter on Ready issues only fresh `ContributorTask`. Show exact ID, instructions,
criteria and both locked accepted-submission/completed-review terms through
existing `api.CompensationAwards`; preserve decimal strings and explicit unpaid.
No context/intake tab or guide request from Ready in this slice. That is a UI
scope cut, not a new backend eligibility rule. From active Mine, Enter first
reads the same exact task; explicit Context/Intake sections invoke their typed
reads independently. Display returned guide document labels, media type, size
and hash without download links or a bytes-verified claim. No eager prefetch.
Submissions Enter freshly reads its selected ID and verifies its returned task
matches the selected own-work row; the response has no project field, so retain
the row's selected-project context without inventing one. Never substitute a
manager projection when contributor reads fail. Task/detail/context/requirements
must also agree with the selected project and exact task; compare returned
guide/version/policy selectors where both sections supply them, never substitute
a current guide for a locked one or present mismatched sections together.

Keep keys minimal: arrows select/scroll, Enter inspect, Tab change section,
Esc back/cancel, `g` project picker, `n` next, `r` refresh, `/` local filter,
`c` inert CLI argv, `?` help, `q`/Ctrl+C quit. No `a`, `y` or mutation form.
CLI handoff shows tokens as separate labelled arguments, never a universally
shell-quoted command. In particular `[workstream, submission, findings, ID]`
is labelled an external manual read; display-only Evidence does not look like
a populated or loading Evidence tab. Handoff never executes or copies anything.

### Request and privacy boundaries

Use a small TUI-owned read-only interface whose method signatures are exactly
the nine existing methods above; `*api.Client` satisfies it directly. No
adapter, transport copy, response reinterpretation or exported generic service
locator. Bubble Tea commands run reads asynchronously under cancellable
contexts; the model never blocks waiting for network I/O. Tag each result with
actor/session and monotonically increasing view-request generation plus exact
project/tab/resource/page selectors. A result applies only to the still-current
request. Project switch, refresh, back navigation, quitting and newer requests
cancel and invalidate older results; cancellation alone is not the stale guard.

On fresh 401/403/404, clear affected rows, detail, filters/continuation and
pending results before displaying denial/concealment. A session-wide auth
failure clears all contributor data and permits quit/help only; no automatic
token retry. A resource-specific denial clears the affected project/view and
returns to an uncached picker on explicit `g`. Treat timeout/5xx as unavailable,
not empty/success: clear detail, show bounded failure and explicit refresh.
No retained content may reappear through a late success after denial. Do not
print raw errors, bodies, headers, token, origin credentials or debug traces;
use safe `api.Failure` code/status/correlation fields only. Quit cancels requests
and restores terminal modes before bounded stderr/exit handling, including a
program error. SIGKILL cannot guarantee terminal restoration; do not claim it.

All server/environment strings cross one TUI text boundary before layout:
escape C0/C1, ESC/OSC/CSI, bidi/format controls and Unicode line separators;
allow wrapping only from application-owned newline/layout logic. Do not parse
Markdown, ANSI, URLs or paths. Escaping precedes width/cell measurement. Existing
`command.safeText` remains unchanged because its command-output owner differs;
the focused TUI helper follows that established rule, not a repository-wide
sanitizer refactor. Bound lists to one fetched page and text to existing client
response limits; viewport rendering must not allocate arbitrary cell grids.

## Acceptance criteria

- [ ] Only `tui` changes terminal modes; rejected non-TTY/JSON/config input
  makes zero network requests and leaves terminal settings untouched.
- [ ] One bound actor can navigate one-page membership, Ready, active Mine and
  own Submissions, then fresh exact details, with the typed public client.
- [ ] Ready never requests assignment-sensitive guide bytes or context/intake
  in this UI; Mine context/requirements retain exact locked lineage and fresh
  denial. No local role check grants or denies a backend read.
- [ ] Explicit next/refresh/filter semantics preserve scope and opaque cursors;
  no background calls, whole-export traversal or implicit product write occurs.
- [ ] Late responses cannot replace current scope, resurrect denied data or
  redraw after quit. Canonical denials never become empty queues.
- [ ] Hostile text cannot execute terminal controls, leak tokens, create URLs
  or shell commands, or overflow the chosen viewport. Stored outcomes and exact
  compensation terms remain observations, not acceptance/fulfillment predictions.
- [ ] Wide/narrow/plain/no-color keyboard operation and teardown pass built
  terminal tests; Evidence/findings are honestly marked manual CLI handoffs.
- [ ] Existing explicit CLI output/exit/flags/subcommand help, complete export
  behavior and tests stay intact; root help gains only the new command.

## Review findings

### Native proof refinement

Inspection of the existing four-runner release workflow found Go tests and
installation proof, but no interactive terminal tests. The current host cannot
provide Windows/macOS interactive custody. Use those existing native runners
instead of leaving an unavailable manual proof as an implicit readiness waiver.
This changes test execution only, not the supported platforms or release channel.
The workflow creates a fresh isolated virtual environment and installs the
complete exact dependency closure using `pip --isolated` with
`--require-hashes --only-binary=:all:` from `requirements-native.txt`.
The direct dependency is `pytest==9.1.1`. Reused HTTP fixtures transitively
import the separate HTTP2 fixture, but the TUI tests do not invoke its TLS
certificate generator. Load cryptography inside that existing generator, not
at module import. This avoids introducing an unused native crypto dependency
or downgrading it merely because 50.0.0 lacks an Intel Mac wheel. Existing HTTP2
tests still use the backend's cryptography dependency and must pass unchanged.
Prove the TUI module collects and executes in the isolated pytest-only closure;
prove the GOAWAY test still executes real TLS/HTTP2 with its existing dependency.
Inspect actual pytest wheel metadata for all four targets and lock every
transitive dependency, including Windows-only dependencies. The backend lock
provides version provenance, not runtime
installation authority: its Linux-only resolution cannot stand in for native
Windows/macOS dependency proof. Obtain wheel hashes from the package index and
verify installation on each target; missing wheels or hashes fail, never fall
back to an unpinned install. No backend runtime, real credentials or new service
is needed for this socket-only suite. The committed native requirements file is
the authoritative input, covered by the existing CLI workflow path selection.

`TUI-CI-001` requires more than JUnit totals. A narrowly scoped pytest runner
records the complete raw node-ID multiset during collection, deselection events,
and every setup/call/teardown report, including `wasxfail`. Clear inherited
selection options and disable automatic third-party plugin loading; load only
the explicit proof plugin and select the exact HTTP test file. Require nonzero
collection, unique node IDs, no deselection, and exactly one successful
setup/call/teardown sequence per collected test. Reject skips, xfail, XPASS,
collection errors, missing/duplicate reports and any nonzero pytest exit.
Cancellation cannot produce a valid completion receipt. Do not infer absence of
deselection or XPASS from standard JUnit. Self-tests must discriminate omitted
tests, duplicates, empty collection, skips, xfail, non-strict XPASS, ordinary
failure and interrupted execution against a valid passing control.

Bind the validated receipt to the actual checked-out source SHA, native target,
workflow run ID and attempt. Keep it outside release-native/assembled assets and
upload it under a separate test-evidence artifact name. The test runner and
receipt verifier both propagate failure to the existing native job and assembly
gate. Retain existing permissions, timeouts and publication behavior. Update
the canonical release runbook to distinguish these interactive tests from
installation smoke checks. `TUI-CI-002` is addressed by the isolated hashed
closure above; direct top-level pins alone are not sufficient.

Terminal error proof is split explicitly: `test_tui_http.py` owns built-process
q/Ctrl+C/pending-quit and signal teardown with observed terminal modes, cursor
and alternate-screen restoration. Signal teardown is not a program-error test.
`cli/internal/command/tui_test.go` injects program-run/output-writer failures
through test-only seams, asserting cleanup before bounded error handling and
observable failure. The proof-table reference to forced program-error paths
uses this Go boundary, not a production fault-injection option. No runtime test
backdoor is introduced. All four native jobs run both proof boundaries.

On Darwin, the terminal observer performs one zero-time read-readiness check
before comparing the complete terminal state. XNU sets transient `PENDIN` when
restoring canonical mode; its readiness path settles pending input processing
without a user-space read. No terminal flags are masked or written by this
observer. A private-PTY regression deliberately injects actual raw mode after
normal CLI teardown and requires the observer to reject it without repair.
Both native macOS architectures must prove this behavior; Linux results alone
