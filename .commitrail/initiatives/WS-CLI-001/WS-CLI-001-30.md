# WS-CLI-001-30 — Distinguish submission history from current revision context

- Initiative: `WS-CLI-001`
- Durable disposition: `Planned`
- Intended merge outcome: Close #499's remaining misleading history presentation and reconcile the existing CLI initiative with the public API gap issues.

## Intent

The two human-readable submission/history commands claim revision changes are
unavailable in the public API. TASK already exposes `revision_context.changes`
through current task work context, but not through immutable submission history.
Keep these different evidence boundaries visible; never join current context
onto historical submissions and represent it as historical truth.

## Bounded change

Allowed: `cli/internal/command/submission.go`, the existing submission HTTP
process test, CLI README, affected roadmap wording, this record, CLI25's stale
current-contract paragraph, initiative overview and index reconciliation.
Prohibited: API/schema changes, extra network requests, submission/replay or
authorization changes, new commands, CI/dependencies, TUI or release packaging.

## Design and acceptance

- Replace the inaccurate message with an explicit absence in this response and
  a `task context TASK_ID` pointer labelled as current, not historical context.
- Preserve exact JSON output and the single authorized request per command.
- Extend existing built-process history proof with text assertions for both
  commands; the original message must fail that proof. No unit-test quota.
- Record #599–#611 as planned public-only client work, not delivered capability.
  Retain #499 rather than create a duplicate issue for the same work.
