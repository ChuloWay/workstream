# WS-CLI-001-24 — Read and export contribution evidence

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: CLI access to the two existing public contribution
  evidence endpoints, without waiting for or duplicating PILOT-02.

## Intent

Add `workstream contributions` (self, optional project filter) and
`workstream project contributions PROJECT_ID` (authorized project export).
Both support the backend's contribution type and half-open recorded-time
filters. Default output is escaped text; `--output json` preserves the full
public projection. `--csv FILE` downloads the server's exact CSV to a new private
file, never stdout or an existing file. CSV and JSON are separate single reads,
not an automatic two-request comparison or locally reconstructed CSV.

The existing public routes are `/api/v1/actors/me/contributions` and
`/api/v1/projects/{project_id}/contributions/export`. Backend AUTH binds the self
actor and permits covering PM or exact-project Finance reads. Earned awards are
not payment/fulfillment claims. No new grant, source record or acceptance path
is created. Local CSV conversion was rejected because the server already owns
formula-safe export and complete snapshot selection.

## Acceptance criteria

1. Use only the two public GETs. Preserve selected UUID spelling in requests,
   compare UUID identity in responses, reject malformed selectors/filters
   before dispatch. No actor selector or local role decisions.
2. Validate the complete JSON envelope and record/award wire shapes, required
   nullable fields, source identities, exact decimal strings and unbounded
   positive version numbers. Bind project/type/time filters and enforce the
   server's 1000-record completeness limit; never truncate or auto-paginate.
3. CSV downloads retain exact server bytes after bounded UTF-8/header/row and
   record validation, including matching selected scope, formula-safe text,
   repeated contribution/award grouping and absence of reflected credentials.
   Validate before publication; create 0600 files atomically without overwrite
   or symlink following. JSON/text remain complete and terminal-safe.
4. Keep shared transport restrictions, sanitized errors and fresh server
   authority. Bound responses at 32 MiB and reject excess without partial output.
   No separate transport framework, local economic decisions or cached grants.
   Local CSV I/O failures report `file_io_error`/exit 1; invalid destinations
   and empty explicit flags report `invalid_arguments`/exit 2. Text diagnostics
   explain the failure without reflecting paths. A real process file-size limit
   proves write failure leaves no published or temporary file.
5. Process regressions cover both wires, filters, malformed/null/unknown facts,
   foreign scope, normalized duplicate IDs, exact quantities, credential and
   terminal safety, CSV formula protection and failed/no-overwrite downloads.
6. Real signed Flow/API/PostgreSQL proof compares CLI reads with existing
   immutable source facts and server CSV, plus empty self, foreign/ungranted,
   revoked and suspended callers. Fixture-arranged retained records do not
   certify a new public acceptance workflow. A target-binding mutant must fail
   the intended regression after its valid control.
7. Real-Git regressions prove one-new-plus-existing reconciliation, rejection
   of multiple new records, invalid existing records and an unavailable base,
   including a base branch that advanced independently of the PR.
