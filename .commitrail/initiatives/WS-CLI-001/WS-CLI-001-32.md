# WS-CLI-001-32 — Inspect active guide and retained intake evidence

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Seven existing public project/guide GETs become coherent, read-only Go CLI commands without transferring policy or authorization authority to the client.

## Intent

Issue #600 closes the public API-to-CLI gap for current active-guide context and exact guide sufficiency, artifact, effective, and pre-submit policy inspection. A manager or auditor needs to compare retained evidence with the current chain before a separate decision. These reads are observations, never a preflight granting later writes or a local activation decision.

## Current behavior

The CLI already has `project guide list/show/readiness/setup/proposal/post-policy` and shared safe transport/output. `backend/app/modules/projects/router.py` exposes all seven requested GETs. Its two historical collections return newest 100 canonical rows without cursor parameters; exact child GETs can inspect older retained IDs. `docs/spec_authorization_service.md` assigns the diagnostic and current-policy reads to local administrative authority, and the active-guide response is a strict current-chain projection.

### Not allowed

- Local readiness computation, approval/activation implication, cached authority, automatic pagination or mutation retry. Existing commands and transport semantics must not change.

## Design and decisions

Add `project active-guide PROJECT_ID`; within the existing `project guide` group add `sufficiency list/show`, `artifact-policy list/show/effective`, and `pre-submit-policy`. Each command sends one GET, preserves successful public JSON, and uses terminal-safe shared text output. API decoding binds all returned project/guide/child identities and policy lineage to exact selectors, validates required/null fields, hashes, time and full integer range, enforces the documented 100-row collection cap and a bounded response size, and rejects bearer reflections. Reuse existing guide path/UUID, policy and output helpers. Do not invent cursor flags: the backend does not offer them for these two lists.

Rejected alternatives: a second inspection root, importing backend models, using `guide readiness` to derive current policy, or treating list position as an exact historical selector.
