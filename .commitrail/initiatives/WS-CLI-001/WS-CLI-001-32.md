## Design and decisions

Add `project active-guide PROJECT_ID`; within the existing `project guide` group add `sufficiency list/show`, `artifact-policy list/show/effective`, and `pre-submit-policy`. Each command sends one GET, preserves successful public JSON, and uses terminal-safe shared text output. API decoding binds all returned project/guide/child identities and policy lineage to exact selectors, validates required/null fields, hashes, time and full integer range, enforces the documented 100-row collection cap and a bounded response size, and rejects bearer reflections. Single/current reads retain the 16 MiB limit. Historical collection limits derive from the backend's 100-row cap and a 4 MiB per-record envelope covering the bounded sufficiency findings and artifact-policy rule fields; the client still rejects an oversized record. Reuse existing guide path/UUID, policy and output helpers. Do not invent cursor flags: the backend does not offer them for these two lists.

Rejected alternatives: a second inspection root, importing backend models, using `guide readiness` to derive current policy, or treating list position as an exact historical selector.

## Review findings

- `QA001`: The first active/current decoder admitted response values excluded by activation and policy semantics, including incomplete policies, second review, unknown decisions/states and nullable current provenance. The repaired decoder enforces current-route literals and non-null bindings while leaving historical report/artifact list/show nullability intact. It does not reproduce backend readiness decisions or recompute policy digests.
- `QA002`: A generic nonblank string-array check rejected schema-valid `minimum_finding_fields: [""]`. String arrays now validate element types within the bounded response; policy enum arrays have a separate nonempty literal check without invented uniqueness or length limits. Built-binary failure and valid-blank/repeated-decision controls cover both findings.
- `EXT001`: The original shared 16 MiB body cap rejected a valid multi-row artifact-policy response before its documented 100-row validation. A 70-row, 17+ MiB built-process reproducer failed at the old head. Collection reads now use the backend row cap and nested-field-derived record envelope, while single/current reads and per-record rejection remain bounded. The same reproducer is the regression control.
