## Design

CON input is immutable scalar source lineage: project/task/submission,
FinalAcceptance, assignment, contributor, frozen policy version, stabilized
artifact hash, correlation UUID and expected lifecycle generation. It has no caller-chosen contribution/award
IDs and no receipt-shaped value purporting to authorize recognition. Existing
SQL source guards validate real stored ancestry. Future shared acceptance owns
actual source authority and TASK terminal-state proof; isolated storage controls
here do not claim those effects or permission.

The caller owns one root AsyncSession transaction and supplies the existing REV
lifecycle fence bound to that same session through a CON-owned acquisition-only
Protocol (`acquire(expected_generation: int) -> object`). External composition
passes the canonical REV implementation structurally; CON imports no REV type,
so the future REV -> CON dependency remains acyclic. No returned scalar is
interpreted as authority. The participant calls `acquire(expected_generation)` first, before any CON/COMPENSATION query or lock;
it never accepts constructible detached facts as proof of custody. The eventual
shared acceptance caller must acquire that same reentrant fence before source
and TASK locks. The transaction stays open through later effects. No
participant commits or rolls back independently. No current policy selection
or adapter availability is re-evaluated: published/retired frozen definitions
remain due even after retirement or binding suspension.

CON loads its exact frozen accepted-submission rule and immutable definitions,
uses source-unique PostgreSQL INSERT ON CONFLICT DO NOTHING plus exact winner
recovery (never catches a uniqueness failure in a broken root transaction),
generates UUIDv7 IDs only for new rows,
and copies the supplied artifact digest unchanged. The compensation owner
receives strict contribution/definition facts through its public port, writes
all awards and returns exact immutable facts. Unpaid means zero; compensated
means one or two exact definitions. Exact replay recovers original IDs and
requires the complete stored award set; conflicts never backfill partial rows.
Correlation is new-award trace metadata: compensated replay checks stored
correlation equality; unpaid replay has no persisted correlation and does not
claim to compare it. Future shared acceptance owns its request idempotency.
Returned facts supply later audit/outbox composition; this chunk does not stage
or claim authorized audit/outbox events.

A deferred SQL constraint trigger verifies complete accepted-submission award
membership at commit, allowing the contribution and awards to be staged in
sequence. It also protects late inserts from changing a completed set. All
protected SQL references are schema-qualified and functions pin safe search_path.
Upgrade refuses incomplete retained accepted-submission rows unchanged. Reviewer
completeness remains with its future participant; existing reviewer storage
proof is retained.

## Acceptance criteria

- Unpaid, money-only, points-only and combined frozen rules create exact records/awards; retired policy and suspended binding do not alter frozen obligations.
- Source replay returns the same record and award IDs; each changed source fact and compensated-award correlation conflict rejects without new rows. Concurrent same-source calls converge through PostgreSQL, not fake locks.
- Real stored foreign source substitutions reject at intended ownership guard, with valid controls; copied decimal quantity, unit, binding, definition and artifact hash equal canonical stored facts.
- In one real fenced root transaction, stage a valid compensated contribution with one of two canonical awards before deferred commit; exact-source replay must conflict without inserting the missing award, then caller rolls back. Removing replay completeness validation must fail the intended conflict assertion (whether the broken code returns a partial set or backfills).
- Caller rollback and late database failure discard new FinalAcceptance/contribution/awards together. No participant commit, provider, ART, AUTH evaluation, Review or task mutation occurs.
- The supplied canonical fence rejects missing root transaction and managed/raw SQL savepoints; independent sessions prove transaction-scoped serialization.
- Direct SQL partial compensated award set fails at deferred commit; full set and unpaid controls succeed; removing the completeness guard makes the negative proof fail. Retained incomplete migration fixture refuses upgrade without repair/deletion.
- Existing paid storage tests must stage complete accepted-submission award sets or retain invalid insert probes in a rolled-back transaction; no required assertion is removed. New tests are registered once in the project lifecycle group (schema has little timing headroom), all existing required storage proof remains, full hosted suite completes with zero skips/deselections. No percentages are acceptance gates.

Fixtures use real retained human-source FinalAcceptance storage; automated no-Review production proof remains with false activation, which is currently blocked. No fixture changes true to false or fabricates AUTH allows.
